# ChronOS 실무 전체 작업 시나리오 및 AI 실행 지시서

> **문서 성격**: 개발 완료된 **ChronOS**(16개 OS 프로그램 · 32종 에이전트 도구 · 3역할 권한 · PC/태블릿/스마트폰 3-디바이스 셸)를 대상으로, **실제 건설·플랜트·제조·범용 프로젝트의 전 생애주기 실무**를 AI(브라우저/Computer-Use 에이전트 또는 Playwright 실행기)가 처음부터 끝까지 그대로 수행·검증할 수 있도록 작성한 **표준 작업 지시서(Executable SOP)**입니다.  
> **기준 코드**: `HEAD f4cdeec` + 최신 조회·보고서·현장 협업 도구 (`docs/demo/시나리오.md` 및 앱 소스는 건드리지 않음)

---

## 0. AI 실행기 공통 규약 (Execution Contract)

작업을 시작하기 전, 실행 에이전트는 아래 규약을 반드시 준수한다.

### 0-1. 접속 대상 및 실행 모드
| 항목 | 운영/시연 서버 모드 (`실 Liner API`) | 격리 E2E/리허설 모드 (`CHRONOS_FAKE_LLM=1`) |
|---|---|---|
| **기본 URL** | `http://localhost:5600` (백엔드 `:8210`) | `bash scripts/e2e-local.sh` 기준 포트 또는 `http://127.0.0.1:5700` |
| **LLM 동작** | 실제 Liner 5종 API 호출 (응답 5~60초+ 소요 가능) | 가짜 LLM(`app.llm.fake`) 즉시 응답 (자연어 답변·차트는 시연용 고정 문구) |
| **검증 기준** | **툴 호출 + 실제 계산 숫자 + 출처 URL + 자연어 논리** 모두 검사 | UI 흐름·버튼·도구 호출 구조 검증 (`[보고서용 그림]`·동적 합성 문구는 실 API 모드에서만 완전 검증) |

### 0-2. 가상 계정 체계 (제5조 가상 데이터 기준)
> **주의**: 실제 비밀번호·API 키를 이 문서나 로그에 평문 하드코딩하지 않는다. 실행 전 환경 변수 또는 운영자 입력으로 초기 관리자 계정 자격 증명을 주입받는다.

| 구분 | 아이디 (`login_id`) | 권한 (`role`) | 용도 및 생성 시점 |
|---|---|---|---|
| **총괄 PM / 관리자** | `ADMIN_ID` (예: 운영 DB 관리자 또는 E2E `demo-admin`) | `admin` (`관리자`) | 초기 접속·계정 승인·설정·개발 콘솔·최종 의사결정 |
| **공정 담당자** | `planner.kim` (이름: `김공정`) | `user` (`사용자`) | **Phase 1에서 신규 회원가입 → 관리자 승인 후 사용** (PC/태블릿 일정·만회안·자료함·보고서 실무) |
| **현장 관리자** | `field.park` (이름: `박현장`) | `field` (`현장 관리자`) | **Phase 1에서 신규 회원가입 → 관리자 승인 후 사용** (스마트폰/태블릿 3탭 현장 점검·사진 보고·공종 의견 회신) |

### 0-3. 공통 대기 · 상태 판별 · 안전 수칙
1. **에이전트 작업 완료 대기 규칙**:
   - 대화창 `보내기` 클릭 후 성급히 다음 동작을 누르지 않는다.
   - 상단 메뉴바 `Computer-Use` 배지(또는 `워크플로우` 진행 리본 `.os-wf-ribbon`)의 상태가 **`진행 중`**에서 **`답변 대기 중` / `승인 대기 중` / `완료` / `실패` / `중단됨`** 중 하나로 바뀔 때까지 기다린다.
   - 실 Liner API 모드에서 `generate.run`, `report.generate`, `shorten.make` 등은 최대 `240초`까지 대기할 수 있다.
2. **사람 승인(`승인함`) 임의 우회 금지**:
   - 승인 수준이 `중요한 것만` 또는 `모두 승인`일 때, 첫 저장·준공일/마일스톤/크리티컬 패스/조건/내 규칙 변경은 반드시 `승인함`에 `대기` 건으로 올라온다.
   - 시나리오에서 명시적으로 `[승인하고 반영]` 또는 `[거부하고 다시 짜게 하기]`를 지시하기 전에는 임의로 승인 설정을 `자동`으로 바꾸지 않는다.
3. **실패 및 예외 기록 규칙**:
   - 어떤 STEP에서 기대 체크포인트가 실패하면 즉시 **`FAIL`** 또는 **`BLOCKED`** 로 기록하고, 관리자 계정으로 **`개발 콘솔 > 실행 추적`** 또는 **`에이전트 구조`** 화면 스크린샷과 오류 문구를 첨부한다.
4. **표준 스텝 작성 형식**:
   - 모든 STEP은 `[수행 역할 / 기기]` → `[사용 경로]` → `[AI 실행 지시]` → `[기대 백엔드·에이전트 동작]` → `[검증 체크포인트]` → `[분기 / 예외 대응]` 순서로 따른다.

## 1. 사전 준비 (PRE-01 ~ PRE-03) — 환경 점검 · 가상 파일 생성 · 작업대 세팅

### `PRE-01`: 서버 상태 확인 및 가상 업무 샘플 파일 3종 준비
- **수행 역할 / 기기**: 실행기(로컬 셸)
- **사용 경로**: 터미널 / 작업 임시 폴더(예: `/tmp/chronos-work-files/`)
- **AI 실행 지시**:
  1. 대상 서버 API 헬스 체크(`GET /api/health`)가 HTTP `200`을 반환하는지 확인한다.
  2. 이 문서 맨 아래 **부록 A**의 파일 내용 3종을 그대로 로컬에 생성한다:
     - `/tmp/chronos-work-files/동절기_콘크리트_시방서.txt`
     - `/tmp/chronos-work-files/협력사_전기설비_공정표.csv`
     - `/tmp/chronos-work-files/발주처_월간공정보고_양식.md`
- **기대 동작**: 파일 3개가 UTF-8 인코딩으로 생성된다.
- **검증 체크포인트**:
  - [ ] `/api/health` 응답 `200 OK`
  - [ ] 3개 파일 모두 0바이트가 아니며 한글 깨짐이 없음
- **분기 / 예외 대응**: 서버가 내려가 있으면 `BLOCKED` 보고 후 중단한다(운영 중인 서버 프로세스를 임의로 재시작하지 않음).

### `PRE-02`: 관리자 로그인 및 AI·날씨·승인 설정 점검
- **수행 역할 / 기기**: `admin` / `데스크톱`
- **사용 경로**: 로그인 화면 → 상단/하단 Dock `설정`
- **AI 실행 지시**:
  1. 로그인 화면에서 접속 화면 선택 버튼 중 **`데스크톱`**을 클릭한다 (`aria-pressed="true"`).
  2. `아이디`, `비밀번호`를 입력하고 **`들어가기`**를 클릭한다.
  3. 바탕화면 하단 Dock에서 **`설정`** 아이콘을 클릭해 설정 창을 연다.
  4. 왼쪽 메뉴에서 다음 관리자 구역을 순서대로 확인한다:
     - **`LLM 연결`**: 기본 연결 상태가 정상인지 확인(미연결 시 운영자에게 키 확인 요청).
     - **`정보 API 연결`**: 기상청 공공데이터 API 연결 상태 확인(미설정 시 Phase 3 날씨 조회에서 fallback 동작 예상).
     - **`작업별 모델 배정`**: `가벼운 일`, `보통 일`, `어려운 일`, `긴 문서 읽기`, `그림 읽기`, `임베딩` 6개 슬롯이 모두 지정되어 있는지 확인.
     - **`승인 수준`**: **`중요한 것만`**이 선택되어 있는지 확인(아니면 `중요한 것만`으로 선택).
- **검증 체크포인트**:
  - [ ] 로그인 후 Dock 및 상단 메뉴바가 정상 렌더링됨
  - [ ] `설정` 8개 구역(`내 정보`, `화면 · 테마`, `차트 · 표 기본값`, `LLM 연결`, `정보 API 연결`, `작업별 모델 배정`, `계정 (관리자·사용자)`, `승인 수준`) 모두 표시됨
  - [ ] `승인 수준` = `중요한 것만`
- **분기 / 예외 대응**: `LLM 연결`이 비어 있으면 AI 호출이 `llm_not_ready`로 중단되므로 실 API 테스트 불가(`CHRONOS_FAKE_LLM=1` 환경이 아니라면 `BLOCKED` 처리).

### `PRE-03`: 개인 작업대(테마 · Dock · 공정률 위젯) 커스터마이징
- **수행 역할 / 기기**: `admin` / `데스크톱`
- **사용 경로**: `설정 > 화면 · 테마` → `앱 목록(Launchpad)` → `공정률` 창
- **AI 실행 지시**:
  1. `설정 > 화면 · 테마`에서 **`야간 모드 (Midnight Aurora)`** 카드를 클릭해 다크 테마 전환을 확인한 뒤, **`주간 모드 (Daylight Sky)`**로 되돌린다.
  2. `에이전트 실시간 작업 화면 연출 (Computer Use 뷰)` 항목이 **`스테이지 창 전환 · 포커스 추적 (Computer Use 권장)`**으로 켜져 있는지 확인한다.
  3. 같은 화면 `Dock · 태블릿 메뉴 구성`에서 **`Dock 아이콘 편집`** 버튼을 클릭(또는 Dock 맨 앞 앱 목록 열기 → `편집` 클릭)해 프로그램 하나를 `Dock에 두기` 해제 후 다시 체크하고 `완료`를 눌러 앱 목록을 닫은 뒤(앱 목록에서 `편집`으로 들어간 경우는 `완료` 후 목록으로 돌아가므로 오른쪽 위 `✕`로 닫는다) 이어서 **`Dock 기본 구성으로 복원`** 버튼을 눌러 기본 상태를 확인한다.
  4. 메뉴바 일정 선택기(`일정 고르기`)에서 **`5층 사무동 신축 · L3`**를 선택한 뒤 Dock **`공정률`**을 연다.
  5. `공정률` 상단 리본에서 **`배치 편집`** 버튼을 클릭 → `위젯 표시` 칩에서 하나를 껐다 다시 켜고, **`기본 배치 복원`** → **`편집 완료`** 순으로 클릭한다.
  6. 확인 후 **`로그아웃` (`메뉴바 오른쪽 사용자 이름 ▾ > 로그아웃`)**을 눌러 로그인 화면으로 나온다.
- **검증 체크포인트**:
  - [ ] 주간/야간 테마 즉시 전환 및 복원 확인
  - [ ] Computer Use 뷰 = `스테이지 포커스 켜짐`
  - [ ] Dock 편집 및 `기본 구성 복원` 동작 확인
  - [ ] `공정률` 위젯 배치 편집 및 `기본 배치 복원` 동작 확인

## 2. Phase 1: 팀원 온보딩 · 권한 분리 · 계정 수명주기 (`STEP 1-1` ~ `1-4`)

> **실무 배경**: 새 현장 공정팀이 꾸려져 본사 공정 담당자(`planner.kim`)와 현장 시공 관리자(`field.park`)가 가입 신청을 하고, PM(`admin`)이 등급을 검토·승인하며 인사 이동/보안 정지 시 비활성화·재활성화를 테스트한다.

### `STEP 1-1`: 본사 공정 담당자 회원가입 신청 (`planner.kim`)
- **수행 역할 / 기기**: 비로그인 사용자 / `데스크톱`
- **사용 경로**: 로그인 화면 → **`회원가입`** 버튼
- **AI 실행 지시**:
  1. 로그인 화면에서 **`회원가입`** 버튼을 클릭해 `회원가입 신청` 모달을 연다.
  2. 다음 값으로 폼을 입력한다:
     - `아이디 *`: `planner.kim`
     - `이름 *`: `김공정`
     - `이메일 *`: `planner.kim@chronos-demo.local`
     - `연락처 (선택)`: `010-2026-1001`
     - `소속 회사 · 현장 (선택)`: `한빛건설 / 5층 사무동 신축`
     - `부서 · 직책 (선택)`: `공정관리팀 · 과장`
     - `비밀번호 *`: 테스트용 임시 비밀번호(예: `plan2026!`)
     - `비밀번호 확인 *`: 동일 비밀번호
     - `신청 등급`: **`사용자 (공정 · 일정 담당자)`** 클릭 (`aria-pressed="true"`)
     - `가입 사유 · 담당 업무 메모 (선택)`: `본사 주간 공정표 및 만회 계획 수립 담당`
  3. **`가입 신청하기`** 버튼을 클릭한다.
  4. 완료 화면에서 아이디·이름·신청 등급·상태(`관리자 승인 대기`)를 확인한 뒤 **`로그인 화면으로 돌아가기`**를 클릭한다.
- **검증 체크포인트**:
  - [ ] 상태 표시 `관리자 승인 대기` 확인

### `STEP 1-2`: 현장 관리자 회원가입 신청 (`field.park`) 및 미승인 로그인 차단 검증
- **수행 역할 / 기기**: 비로그인 사용자 / `데스크톱`
- **사용 경로**: 로그인 화면 → **`회원가입`** → 로그인 시도
- **AI 실행 지시**:
  1. 다시 **`회원가입`** 버튼을 클릭해 현장 관리자 계정을 신청한다:
     - `아이디 *`: `field.park`
     - `이름 *`: `박현장`
     - `이메일 *`: `field.park@chronos-demo.local`
     - `연락처 (선택)`: `010-2026-2002`
     - `소속 회사 · 현장 (선택)`: `한빛건설 / 5층 사무동 신축`
     - `부서 · 직책 (선택)`: `골조시공팀 · 현장소장`
     - `비밀번호 *` / `확인 *`: 테스트용 임시 비밀번호(예: `field2026!`)
     - `신청 등급`: **`현장 관리자`** 클릭 (`aria-pressed="true"`)
     - `가입 사유 · 담당 업무 메모 (선택)`: `현장 일일 체크인 및 사진 진도 보고 담당`
  2. **`가입 신청하기`** → **`로그인 화면으로 돌아가기`**를 클릭한다.
  3. **예외 검증(미승인 로그인 차단)**: 로그인 폼에 `field.park` / 해당 비밀번호를 입력하고 **`들어가기`**를 눌러 로그인이 거부되는지 확인한다.
- **검증 체크포인트**:
  - [ ] 미승인 계정의 로그인 시도가 차단되고 오류 배너(`.os-card-error`)가 표시됨
- **분기 / 예외 대응**: 이미 `planner.kim` 또는 `field.park`가 이전 테스트로 DB에 존재하면 아이디 뒤에 날짜/회차 접미사(예: `planner.kim2`)를 붙여 진행하거나 기존 계정을 먼저 확인한다.

### `STEP 1-3`: 관리자 가입 승인 대기열 검토 및 승인 처리
- **수행 역할 / 기기**: `admin` / `데스크톱`
- **사용 경로**: `설정 > 계정 (관리자·사용자)` → `가입 승인 대기`
- **AI 실행 지시**:
  1. 관리자 계정으로 **`데스크톱`** 로그인한다.
