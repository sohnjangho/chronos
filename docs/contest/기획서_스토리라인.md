# ChronOS 기획서 스토리라인 (rev4 뼈대 — PM 확인용)

> 기준: 개발 폴더 `feature/plan-1` `adae615`(2026-11-24 15:38). 앱 18개 + 「현장 점검」, 계획 1~4 완료(계획 4 는 조건부 Task 94 만 남음 — 쓰지 않는 대체 경로).
> 이 문서는 **기획서 rev4·시연 영상·결선 발표를 같은 이야기로 묶는 뼈대**다. PM 이 고르면 rev4 원고와 영상 대본을 이 순서로 쓴다.

## 1. 한 문장 이야기

> **"비 온 다음 날 아침, 공정표를 다시 짜고 · 근거를 붙이고 · 사람이 결정하고 · 협력사에 전화까지 — 15년차 PM이 반나절 걸리던 일을 ChronOS 는 한 시간 안에 끝낸다."**

심사 기준 네 개를 **한 현장의 일주일**로 보여 준다. 기능을 나열하지 않고, 사건이 생길 때마다 그 기능이 등장한다.

| 이야기 축 | 심사 기준 | 이야기에서 맡는 것 |
|---|---|---|
| 「또 바뀐다」 | 문제 정의 30 | 주인공(현장 PM)의 반복되는 밤샘 |
| 「한 현장의 일주일」 | 완성도 30 | 실제로 도는 화면으로 사건을 하나씩 해결 |
| 「누가 무엇을 하나」 | Liner 활용 20 | 장면마다 Liner 5종 중 무엇이 일했는지 표시 |
| 「다음 현장, 다른 산업」 | 확장성 20 | 같은 엔진으로 생산 현장·외국인 작업자·협력사까지 |

## 2. 전체 흐름 (기획서 장 순서)

```
0. 표지·한 문장          「밤새 고친 공정표, 아침이면 또 바뀐다」
1. 문제 (30)            주인공의 하루 — 4대 병목 · 왜 P6·엑셀·챗봇으로 안 되나
2. 해법의 원칙           계산은 코드 · 판단은 Liner · 결정은 사람 · 연락은 하네스를 거친 AI
3. 한 현장의 일주일 (30)  장면 7개 — 착수 → 근거 → 지연 → 만회 → 현장 확인·연락 → 현장 보고 → 월간 보고
4. 믿을 수 있는 이유      하네스 · 승인 · 버전 · 개발 콘솔 · 검증 수치
5. Liner 활용 지도 (20)  장면 × Liner 5종 표
6. 확장성 (20)           생산 분야 · 전 산업 합성 · 여러 언어 · 3기기 · 정보 API · 협력사
7. 만든 것 / 설계만 된 것 · 규정 준수 · 만든 사람
```

## 3. 1장 — 문제: 주인공의 하루

**주인공**: 5층 사무동 신축 현장 PM(가상). 공정 담당·현장소장과 함께 일함.

| 시각 | 일어나는 일 | 지금 방식 | 병목 |
|---|---|---|---|
| 07:00 | 밤새 비 — 골조 3일 늦어짐 | 엑셀 공정표를 열어 선후행·크레인 겹침을 손으로 다시 셈 | **① 재계산** (반나절~밤샘) |
| 10:00 | 발주처 "준공은 그대로" | 동절기 타설 기준·법규·날씨를 따로 찾음 | **② 근거** (수 시간) |
| 13:00 | 만회하려면 크레인 1대 더 | 크레인 업체·철근 협력사에 전화 돌림, 담당자 부재·통화 내용 기록 없음 | **③ 연락** (〔실측〕) |
| 17:00 | 협력사들이 보낸 엑셀 공정표 | 양식 제각각, 빈 칸 확인·수기 입력 | **④ 취합** (건당 2~3시간) |
| 22:00 | 주간·월간 보고서 | 회사 양식에 숫자 옮겨 적기 | (보고 반복) |
| 다음 날 | 또 바뀜 | — | 처음부터 다시 |

**왜 기존 도구로 안 되나** (rev3 표 유지): P6 = 비싸고 현장·AI 와 단절 / 엑셀 = 계산 없음 / 범용 챗봇 = 날짜가 깨지고 승인이 없고 현장 밖 사람에게 닿지 못함.

```

```

## 5. 3장 — 한 현장의 일주일 (장면 7개)

각 장면 = **사건 → ChronOS 가 한 일(화면) → 결과 숫자 → 쓰인 Liner API**. 괄호는 앱 이름.

### 장면 1 · 월요일 — 착수: 말 한 줄로 공정표
- 사건: "5층 사무동, 3월 착공·연말 준공" 공정표가 필요.
- 화면: (에이전트 대화) 한 줄 → (질문지) 2단계 맞춤 질문, 답 안 한 것은 가정 → 생성 카드(WBS → 초안 → 코드 계산 → 하네스 위반 → 고침 → 통과, 「가정한 것」) → (승인함) 첫 저장 승인 → (간트차트)·(CPM) 크리티컬 패스.
- 덧붙임: 협력사 CSV 공정표를 대화에 붙이면 자동 감지 → 빈 칸만 질문 → 일정 초안(병목 ④).
- 결과: 〔실측: 첫 요청 → 승인까지 분〕, 액티비티 59개.
- Liner: Model(조건 추출 light · 생성 hard · 질문지), Router.

### 장면 2 · 화요일 — 근거: 우리 회사 기준 + 법규 + 날씨
- 사건: "동절기 타설 기준이 우리 시방서랑 법규에 뭐라고 돼 있지?"
- 화면: 대화에 시방서 PDF·현장 사진 첨부 → (자료함) 5축 자동 분류 → 출처 붙은 답 + 근거 카드(법령 검색 *.go.kr 표시, 기상청 날씨) → 같은 근거는 30일 다시 씀.
- 결과: 근거마다 출처 링크, 근거 없으면 「미확인」.
- Liner: Embeddings(자료함 뜻 찾기), Search(web·scholar), MCP(search_legal·search_business), Model vision(사진 읽기).

### 장면 3 · 수요일 아침 — 지연: 비 3일
- 사건: "지상 골조가 비 때문에 3일 늦어졌어" (스케줄에서 A1210 을 고른 채).
- 화면: 대화가 「보는 중: 스케줄 · A1210」 → 지연 영향 카드(준공 +3일, 여유 흡수, 새 크레인 겹침) → (지연 기록) 자동으로 열림, 책임·비용 → (공정률) S-커브에 지연 반영 점선, SPI.
- 결과: 영향 계산 1초대, 계획(Plan)은 승인 전까지 그대로.
- Liner: Model(요청 해석). 계산은 코드.

### 장면 4 · 수요일 오후 — 만회: A안 B안, 그리고 "크레인 2대면?"
- 사건: 발주처 "준공은 그대로".
- 화면: [만회 계획 요청] → 만회안 A(병행)·B(압축·크레인 1→2대) → (비교판) 같은 차트·요약 표 → [+ 만약에 복사본] → (조건·규칙) 크레인 수를 바꾸면 즉시 「준공 A → B · 위반 0」, 간트 점선 미리 보기.
- 결과: 만회 계획 달성률 〔실측: 100% (24/24일)〕.
- Liner: Model hard(만회안 설명·추천). 후보 탐색·계산은 코드.

### 장면 5 · 목요일 — 현장 확인과 연락: AI 가 크레인 업체에 전화 ★하이라이트
- 사건: B안을 승인하기 전에 "크레인 업체가 다음 주 화요일 투입 가능한가, 공종 팀장은 해낼 수 있다고 보나?"
- 화면:
  1. (공정률 › 현장 점검) 만회안 B 공종 의견 조회 → 팀장 회신 「조건부 가능」.
  2. (연락처) 크레인 업체 담당자 → [전화 걸기] 목적·물어볼 것·말하지 않을 것 → **AI 전화**(첫마디 「이 통화는 기록됩니다」, 반대 성별 음성) → 통화 카드: 받아쓰기·요약·**질문별 답과 근거 발화**.
  3. 통화 중 "금액은요?" → 범위 밖이라 답하지 않고 기록(연락 하네스 S-05).
  4. (승인함) 만회안 반영 승인 → 새 버전, (CPM) 완료 예정 당겨짐.
- 결과: 통화 결과가 일정 옆에 남음(병목 ③). 실제 통화 첫 응답 약 1.1초(11-24 실측).
- Liner: Model(통화 목적·질문 초안, 통화 요약, 문자 초안). 실시간 음성은 Gemini Live(지연 때문).

### 장면 6 · 금요일 — 현장이 먼저 말한다: 폰 체크인·사진·걸려 온 전화
- 사건: 현장 관리자가 폰으로 보고, 철근 협력사가 직접 전화해 "자재가 하루 늦는다".
- 화면: (스마트폰 · 현장 점검) 일일 체크인 → 사진 AI 판독(추정 진도율·근거, 못 읽으면 「판독하지 않음」) → 승인함으로. **걸려 온 전화**를 AI 가 받아 번호로 등급 확인 → 「확인할 보고」 → [지연 기록 만들기]. D-3 핸드오프 점검.
- 결과: 현장 관리자는 일정을 못 바꾸고(서버가 막음) 보고만 — 결정은 사무실 사람이.
- Liner: Model vision(사진), Model(받은 문자 자동 답·번역).

### 장면 7 · 월말 — 월간 보고서: 회사 양식 그대로
- 사건: 발주처 월간 공정 보고.
- 화면: (보고서) 지난달 보고서 파일을 올려 양식 학습 → [+ 보고서 만들기] → 공정 요약 글·S-커브·SPI·지연·만회 대책 블록 → 블록마다 "더 짧게" 고치고 「다음에도 기억」 → PDF·Word. Liner 차트는 그림 속 숫자를 표와 전수 대조.
- 결과: 표 숫자는 모두 코드 값, 차트 값 〔15/15 일치〕.
- Liner: Model(서술·수정·양식 학습), Visualization(차트).

## 8. 6장 — 확장성: 다음 현장, 다른 산업

1. **다른 산업** — 생산 현장 「브래킷 BR-200 2만 개」를 같은 엔진으로: 설비 자원별 간트, 「프레스 작업 금지」 띠, 납기선. 처음 보는 산업은 분야 팩을 즉석 합성.
2. **앱 밖의 사람** — 협력사 담당자는 앱을 깔지 않아도 문자·전화로 일정 흐름에 들어온다. **여러 언어 통화**로 외국인 작업자·해외 현장까지.
3. **어느 기기든** — 본사 PC OS, 태블릿 좌우 분할, 현장 폰. 열어 둔 창·탭은 계정별로 기억해 기기를 바꿔도 이어진다.
4. **회사마다 다른 것** — 정보 API 범용 연결(공공 데이터를 설정에서), 보고서 양식 학습·프로젝트 간 재사용, 내 규칙 축적, 스킬 저장.
5. **조직 운영** — 회원가입 승인, 3등급, 프로젝트 격리, 기기 접속 현황·기기 로그아웃.
