## 1. 중심 문장

> **「일정은 매 순간 바뀐다. 무엇이 약속을 늦추는지는, 바뀔 때마다 다시 정해진다.」**

> 시너지: **CPM 이 "어디를 지켜봐야 하는지"를 정하고, Liner 가 "그곳에 무슨 일이 생길지"를 근거와 함께 찾아온다.**

## 2. 논리 사슬 (기획서 전체가 이 순서를 따른다)

```
① 스케줄은 약속이다                마지막 날짜 = 발주처·고객·팀과의 약속
② 스케줄은 매 순간 바뀐다            날씨·자재·사람·설비·요구 — 산업 공통
③ 같은 변동도 영향은 다르다          여유 있는 작업 3일 = 영향 0 / 크리티컬 1일 = 약속 1일 (CPM)
④ 변동이 쌓이면 관리 포인트가 옮겨 간다  어제 여유 있던 작업이 오늘 크리티컬
⑤ 사람은 처음 그린 크리티컬만 본다      옮겨 간 포인트를 놓친다 → 약속이 늦어진다
⑥ 그래서 에이전트가 필요하다          변동마다 → 영향을 재고(코드) → 새 포인트를 짚고
                                    → 그곳의 바깥 위험을 찾고(Liner) → 담당자에게 확인하고
                                    → 사람이 결정한다. 이 한 바퀴를 쉬지 않고.
```

심사 기준과의 대응:

| 기준 | 논리 사슬에서 | 보여 주는 것 |
|---|---|---|
| 문제 정의 30 | ①~⑤ | 산업 공통의 본질 + 15년차 PM 이 실제로 놓쳐 본 순간 |
| 완성도 30 | ⑥ 한 바퀴가 실제로 돈다 | 시연 핵심 장면 「같은 3일, 다른 영향」 |
| Liner 활용 20 | ⑥의 바깥 위험·근거·글·판단 | 한 바퀴 단계마다 쓰인 Liner 7가지 |
| 확장성 20 | ②가 산업 공통 | 같은 엔진 + 분야별 바깥 자료 갈래 |

## 4. 1장 — 문제: 약속은 어디서 늦어지나

### 1-1. 본질 (산업 공통, 그림 한 장)
- 같은 네트워크에 **같은 3일 지연 두 건**을 그린 그림: 왼쪽은 여유에 흡수(준공 그대로), 오른쪽은 크리티컬이 옮겨 가 준공 +3일. "크기가 아니라 **위치**가 약속을 늦춘다."
- 산업 예시 한 줄씩: 건설(타설·양중) · 생산(설비·금형) · 연구개발(시험 장비·인증) · 사업화(인허가·계약).

### 1-2. 사람이 놓치는 까닭
| 까닭 | 실제 모습 |
|---|---|
| 변동마다 전체를 다시 계산할 수 없다 | 엑셀 공정표는 주간 회의 때 손으로 고친다 |
| 계산해도 "지금 어디를 봐야 하나"를 매번 판단할 수 없다 | 처음 정한 크리티컬 패스를 계속 본다 |
| 포인트를 알아도 그곳의 바깥 위험(날씨·자재값·환율·업체)을 따로 찾아야 한다 | 담당자 경험과 감에 맡긴다 |
| 담당자에게 바로 확인할 수 없다 | 전화를 돌리고, 통화 내용은 남지 않는다 |

### 1-3. 기존 도구로 안 되는 까닭
| 도구 | 하는 것 | 못 하는 것 |
|---|---|---|
| P6 · MS Project | 계산 | 포인트 이동을 알려 주지 않음, 바깥 위험·연락 없음, 비싸고 어려움 |
| 엑셀 | 기록 | 계산 없음 |
| 범용 AI 챗봇 | 말 | 날짜가 깨짐, 출처 없음, 승인 없음, 현장 밖 사람에게 닿지 못함 |

### 1-4. 만든 사람의 한 장면 (PM 확정 11-24 — 가상화한 실제 유형)
- **크리티컬 패스를 당겨 끝냈는데, 다음 작업을 시작할 수 없었다.**
  - 골조가 크리티컬이라 야간 작업까지 넣어 골조를 앞당겨 끝냈다.
  - 그런데 다음 외장 작업은 시작하지 못했다. 그사이 커튼월 제작 도면 승인과 수입 자재 반입이 늦어져, **진짜 약속을 정하는 줄은 이미 그쪽으로 옮겨 가 있었다.**
  - 골조를 당기느라 쓴 돈과 사람은 준공을 하루도 당기지 못했다.
- 교훈: **관리 포인트는 내가 마지막으로 본 자리에 머물러 있지 않다.** 힘을 쏟기 전에 "지금 약속을 정하는 줄이 어디인가"를 다시 봐야 한다 — 이것을 매 변동마다 대신 해 주는 것이 에이전트다.

## 5. 2장 — 해법: 에이전트의 한 바퀴

```
   ┌──────────── ① 변동이 들어온다 ◀──────────────────────────┐
   │   대화 한 줄 · 현장 체크인 · 사진 · 걸려 온 전화·문자 · CSV      │
   ▼                                                            │
 ② 영향을 잰다 (코드 — CPM·달력·자원, 오차 0%)                        │
   ▼                                                            │
 ③ 관리 포인트를 다시 짚는다 (코드 — 크리티컬 + 여유 ≤ 3일, 3주 창)      │
   ▼                                                            │
 ④ 새 포인트의 바깥 위험을 찾는다 (Liner + 기상청)                     │
   ▼        날씨 · 금속·원자재 · 환율 · 업체 소식, 출처 문장까지          │
 ⑤ 담당자에게 확인한다 (Liner 글 + AI 전화, 연락 하네스)                │
   ▼                                                            │
 ⑥ 대안을 견주고 사람이 결정한다 (만회안 · 비교판 · 승인함)              │
   ▼                                                            │
 ⑦ 새 버전 → 포인트 다시 계산 ─────────────────────────────────────┘
```

분업 표:
| 누가 | 하는 일 | 하지 않는 일 |
|---|---|---|
| 코드 | 날짜·여유·자원·영향·관리 포인트 계산, 하네스 점검 | 판단 |
| Liner | 요청 해석, 어떤 바깥 자료를 볼지 고르기, 출처 있는 검색·문장, 연락 글·통화 요약, 설명·보고서·차트 | **날짜 계산, 숫자 지어내기** |
| 사람 | 승인·거부, 조건 확정, 연락 보내기(기본) | — |
| 연락 하네스 | 시험 모드·근무시간·권한·번호 비공개·근거 대조 | — |
