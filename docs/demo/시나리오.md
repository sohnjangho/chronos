# 데모 영상 시나리오 — 초안 (묶음 1 범위)

> 5분 이내 · FHD 1920×1080 · 밝은 테마 · 화면 녹화 + 말(자막 겸용).
> 범위: 묶음 1(대화로 만들기 · 질문지 · 생성 회차 · 승인 · 간트·CPM · 조건 미리 보기 · 버전 되돌리기).
> 묶음 2(지연 기록·만회안·비교판·공정률·근거 검색)는 계획 2 Task 42 에서 이 문서에 장면을 더한다.
> 예시 자료는 전부 가상이다(「5층 사무동 신축」, 계정 demo-admin).

## 촬영 전 준비

| 할 일 | 방법 |
|---|---|
| 깨끗한 자료 폴더 | 시연 전용 `CHRONOS_DATA_DIR`(PM 앱의 `data/` 와 따로) |
| 예시 일정 | `python -m app.seed demo` — 시연 일정 둘: 「5층 사무동 신축」(건설·L3, 액티비티 59개·조건 14개·주요 자원 3개, 실적 일부·Data Date 2027-04-17) · 「가상 부품 공장 — 브래킷 BR-200 2만 개」(생산·L3, 액티비티 30개·주요 자원 6개, 납기 2027-09-10, 실적 없음 — 간트는 자원별로 묶이고 「프레스 작업 금지」 띠·「납기 09.10」 선이 보인다) |
| 스케줄 칸 | 스케줄표의 열 고르기는 사람마다 저장된다. 한 번이라도 열을 고른 사람은 생산 일정에서도 「주요 자원」 칸이 저절로 켜지지 않으니 [열]에서 직접 켠다 |
| Liner 연결 | 설정 > LLM 연결에 키, 작업별 배정은 기본값(light=cost · normal=balanced · hard=quality) |
| 승인 수준 | 「중요한 것만」(기본값) — 첫 저장·조건 바꿈이 승인함으로 간다 |
| 리허설 | `bash scripts/e2e-local.sh` 로 화면 흐름 확인(가짜 LLM). 실제 촬영은 Liner 로 |
| 예비 | 생성이 느리거나 실패하면 장면 3을 씨앗 일정으로 바로 넘어간다(말은 그대로) |

| 4 | 2:05–2:30 | 승인함 → 첫 저장 건(사유·요약) → [승인] → 버전 1 | 일정을 바꾸는 결정은 사람이 합니다. 중요한 변경만 승인함으로 옵니다. |
| 5 | 2:30–3:15 | 메뉴바 일정 고르기 「5층 사무동 신축」 → 간트차트(Plan 줄 + Actual·예측 줄, CPM 층 빨강·여유 꼬리, Data Date 선, 「완료 예정」·「크리티컬」 표) | 실적이 들어간 현장입니다. 파란 막대가 Plan, 아래 줄이 실적과 예측입니다. 빨간 것이 크리티컬 패스, 준공이 8일 늦어질 것으로 계산됩니다. |
| 6 | 3:15–4:05 | 조건·규칙 창(네 겹: 기본 · 분야 · 내 규칙 · 입력) → 「자동 점검 안 됨」 표시 → 타워크레인 1 → 2 → 「준공 10.29 → 09.24 · 위반 0」 → 간트의 점선(옮기기 전 자리) → [확정] → 승인함에서 승인 → 버전 3(씨앗이 이미 버전 2 — 실적 입력) | 조건을 바꾸면 바로 다시 계산됩니다. 크레인을 한 대 더 쓰면 준공이 한 달 당겨집니다. 점검하지 않은 조건은 통과로 보이지 않습니다. |
| 7 | 4:05–4:35 | 탐색기 → 버전 목록(1 처음 계획 · 2 실적 입력 · 3 크레인 2대) → **버전 2로 되돌리기** → 버전 4, 준공 예측이 다시 10.29 | 모든 변경은 버전으로 남고, 언제든 되돌릴 수 있습니다. |
| 8 | 4:35–5:00 | 설정 > LLM 연결의 작업별 모델 배정 → 개발 콘솔(관리자) 사용량 | 두뇌는 Liner Model API 입니다. 작업 난이도에 따라 라우팅 전략을 나눠 씁니다. 공정표를 판단하는 사람의 방식을 실행하는 에이전트, ChronOS 입니다. |

합계 5:00. 장면 2~3 은 Liner 응답 시간에 따라 편집에서 줄인다(대기 구간 빨리 감기 표시).
