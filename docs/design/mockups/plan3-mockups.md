## 1. 외부 사례 메모 (기억으로 정리, 웹 확인 안 함)

**Claude(claude.ai)** — 입력칸 왼쪽 「+」(파일·사진)로 붙이거나 창에 끌어 놓는다. 붙인 파일은 입력칸 위에 작은 카드로 줄지어 보인다. 사진은 썸네일, 문서는 이름과 종류(PDF, 줄 수)가 보인다. 올리는 동안에는 카드 위에 진행 표시가 돈다. 보낸 뒤에는 말풍선 위에 같은 카드가 남는다. 프로젝트 기능에는 「지식」 칸이 따로 있어, 파일 목록과 쓴 용량을 대화 밖에서 본다. 모델 고르기는 입력칸 근처의 작은 펼침 단추이고, 대화 중에 바꿔도 이어서 쓴다.

**ChatGPT** — 모델 이름이 대화 창 머리 왼쪽에 「모델 ▾」로 늘 보인다. 펼치면 모델마다 한 줄 설명이 붙는다. 첨부는 입력칸 안 타일이다. 사진은 썸네일에 원형 진행 표시, 문서는 색 아이콘에 이름과 종류가 붙는다. 창에 끌어 놓으면 창 전체가 「여기에 놓기」 판으로 덮인다. 받지 않는 형식은 짧은 알림으로 거절한다. 「내 파일」 같은 모아 보기는 대화와 따로 떨어져 있다.

**Google Drive** — 찾기 칸이 맨 위에 있고, 그 아래 필터 칩(종류 · 사람 · 고친 날 · 위치)이 하나씩 펼쳐진다. 왼쪽 탐색 줄은 「필터」가 아니라 「장소」(내 드라이브 · 공유 문서함 · 최근)이다. 목록과 격자를 바꿔 볼 수 있다. 오른쪽 「세부 정보」 판에는 미리 보기 · 위치 · 활동이 나온다. 찾기 결과에는 맞은 글 조각이 거의 보이지 않는다.

**Notion** — 데이터베이스 보기에서 속성마다 「상태: 완료 ▾」 같은 필터 칩을 쌓는다. 값 목록에서 새 값을 바로 만들 수 있고, 값마다 색이 붙는다. 전체 찾기(⌘K)는 창으로 뜨며 페이지 제목과 맞은 줄을 보이고, 위에 「만든 사람 · 날짜 · 위치」 필터 칩이 있다. AI 답에는 출처 페이지가 번호로 붙는다.

**ChronOS 에 가져올 것**
1. **칩은 짧게, 까닭은 다른 곳에.** 두 채팅 서비스 모두 칩에는 이름과 상태 표시만 둔다. 실패 까닭처럼 긴 글은 칩 밖(트레이 아래 한 줄이나 패널)에 둔다. → B·C 는 이렇게 했고, A 는 칩 안에 넣어 칩이 길어진다.
2. **모델 이름이 늘 보이고 「이 대화만」이라고 밝힌다.** ChronOS 는 일정 만들기·점검·분류가 고른 모델을 따르지 않고, 그림 턴은 따로 바뀐다. 그래서 펼침 아래에 이 범위를 한 줄로 반드시 적는다(세 안 모두).
3. **축이 다섯으로 고정이고 개수가 중요하면 칩보다 레일·열이 낫다.** Drive·Notion 의 칩은 필터가 몇 개 없을 때 좋다. 값과 개수를 한눈에 훑으려면 왼쪽 레일(A)이나 열 브라우저(C)가 빠르다.
4. **찾기 결과에 「어디가 맞았는지」(쪽·시트 행)를 보인다.** Drive 는 이것이 약하다. ChronOS 는 "출처 없이 인용하지 않는다"가 원칙이므로, 자료함에서도 맞은 조각과 쪽을 보여 사람이 같은 근거를 확인하게 한다(B·C 강함, A 는 미리 보기에서만).
5. **되돌리기 어려운 큰 작업(전부 다시 넣기)은 숫자로 확인받고, 끝날 때까지 옛것을 쓴다.** 두 서비스에는 같은 사례가 없다. 그래서 확인 창에 자료 수 · 조각 수 · 시간 · 비용 참고를 적고, 진행률을 설정과 자료함 두 곳에 보인다.

## 2. 안마다 다른 점

### 대화 첨부 `ChatAttach.dc.html`
- **A 입력칸 칩 줄** — 입력칸 안 위쪽에 한 줄 칩(상태·까닭이 칩 안)을 두고, 모델 ▾ 는 대화 머리 오른쪽 알약, 「이 대화의 파일」은 컨텍스트 탭 안 구역 하나로 둔다. 지금 화면에 칩만 더하는 안이다.
- **B 타일 트레이 · 파일 탭** — 사진은 썸네일 타일, 문서는 아이콘 카드다. 실패 까닭은 트레이 아래 한 줄에 둔다. 모델 ▾ 는 대화 머리 왼쪽 맨 앞에서 두 칸 펼침(묶음 | 모델·가격), 「이 대화의 파일」은 패널의 「파일 8」 탭으로 따로 둔다.
- **C 줄 목록 · 파일 띠** — 붙일 파일을 한 줄씩 보인다(크기·진행·까닭 전부, 접을 수 있음). 「이 대화의 파일」은 대화 머리 아래 띠로 두어 패널을 접어도 보인다. 모델 ▾ 는 창 제목 줄 오른쪽, 출처는 번호 각주로 단다.

### 자료함 `Library.dc.html`
- **A 왼쪽 축 레일 · 세 칸** — 왼쪽에 다섯 축의 체크 목록(값·개수·「새」), 가운데 표, 오른쪽 상세(미리 보기·축 고치기)를 둔다. 합치기 제안은 표 위 노란 띠에 둔다. 기존 탐색기와 같은 짜임이다.
- **B 위 칩 · 카드 격자 · 서랍** — 찾기를 먼저 둔다. 축은 찾기 칸 아래 칩 다섯을 하나씩 펼쳐 고른다. 결과는 미리 보기 카드 4열로 보이고, 고르면 오른쪽 서랍에 맞은 곳 목록이 맨 위에 온다. 합치기 제안·지워진 파일은 위 탭에 둔다.
- **C 축 열 브라우저 · 큰 미리 보기** — 다섯 축을 위 다섯 열로 한 번에 보인다. 아래 왼쪽은 맞은 조각이 붙은 목록, 오른쪽은 큰 쪽 미리 보기다(맞은 곳 강조, 쪽 넘김). 합치기 제안은 목록 아래 줄에 둔다.

### 설정 `SettingsFiles.dc.html`
- **A 지금 두 단 그대로** — 고른 설정 시안(LLM 연결 | 배정)에 「그림 읽기」·「임베딩」 두 줄을 더한다. 확인은 가운데 창(모달), 진행률은 임베딩 줄 아래 펼침, 「정보 API 연결」은 LLM 연결 아래 같은 모양의 카드(서비스마다 상태 줄)다.
- **B 넓은 표 · 단계 띠 · 메뉴 나눔** — 배정을 「대화·일정 / 파일·자료함」 묶음의 넓은 표로 만든다. 확인은 옆 판(표를 밀어냄), 진행률은 쪽 맨 위 네 단계 띠(새 모음 → 다시 넣기 → 찾기 바꾸기 → 옛것 지우기)다. 정보 API 는 자기 메뉴 쪽에서 연결 × 서비스 표로 보인다.
- **C 카드 배정 · 프리셋 마법사** — 배정을 2열 카드로 만들고, 확인은 창 없이 임베딩 카드 안에서 받는다. 진행률은 쪽 아래 작업 줄(원 그래프)이다. 정보 API 는 LLM 연결 추가와 같은 세 단계 마법사(종류 → 키 → 서비스별 테스트)다.

(설정 시안의 노란 ①② 꼬리표는 「고른 직후」와 「시작한 뒤」를 한 화면에 같이 보이려고 붙인 설명용이다. 실제 화면에는 없다.)

## 3. 추천

- **대화 첨부: A** — PM 이 비교한 Claude 채팅과 가장 닮았다. 고른 ChatLarge 시안을 거의 그대로 두고 칩만 더하니, 묶음 2 화면(Task 39)과 겹치는 곳이 가장 적다. 다만 칩 안의 긴 실패 까닭은 B 처럼 칩 아래 한 줄로 빼기를 권한다(칩은 「✕ 실패」까지만).
- **자료함: A** — 다섯 축의 값과 개수를 한 번에 훑을 수 있고, 기존 탐색기와 짜임이 같아 일반 사용자가 낯설지 않다. 관리자 합치기 제안도 자리가 분명하다. 시연 장면 3(근거 찾기)을 살리려면 C 의 「목록 줄에 맞은 조각·쪽」 한 줄만 A 의 표 둘째 줄에 더하면 된다.
- **설정: A** — 이미 고른 설정 시안의 두 단 짜임을 그대로 쓴다. 가운데 확인 창이 "전부 다시 넣는다"는 무게를 가장 분명히 전한다. 진행률이 어디까지 왔는지 더 분명히 보이려면 B 의 네 단계 글만 진행 줄에 빌려 오면 된다.

세 추천 모두 「지금 화면에 더하기」 쪽이다. 까닭은 마감(11-25)과, 고른 시안을 이미 만든 화면과 겹치지 않게 하는 데 있다. B·C 는 각각 「사진이 많은 현장」(B)과 「근거 확인」(C)에 강하니, PM 이 무엇을 더 중히 보는지에 따라 고르면 된다.
