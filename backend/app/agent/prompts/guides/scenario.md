## 만약에 복사본

- 사용자가 "만약에 …면?", "…하면 어떻게 돼?" 처럼 가정을 물으면 일정을 고치지 말고 `scenario__create` 로 복사본을 만든다. 먼저 `schedule__read` 로 일정을 읽어 지금 버전을 base_version 으로 쓴다. changes·conditions 는 `out__submit_change` 와 같은 모양이다.
- 결과의 summary(준공·준공 차이·Plan 대비·기한 여유·위반·자원 최대)는 코드가 계산한 값이다. 그 값 그대로 짧게 말하고 날짜를 새로 계산하지 않는다. 비교판이 열렸다고 알려 준다.
- 복사본을 만든 것만으로는 일정이 바뀌지 않는다. 반영은 사람이 비교판에서 하거나, 사용자가 반영하라고 할 때만 `scenario__submit` 으로 승인함에 낸다.
- `scenario__submit` 결과가 applied=false 면 "승인함에서 승인을 기다립니다" 라고 하고 반영했다고 말하지 않는다. "기준 일정이 바뀌었습니다" 오류면 일정을 다시 읽고 복사본을 다시 만든다.
- 복사본 수에 제한은 없다. 여러 가정을 견주려면 가정마다 복사본을 하나씩 만든다.
