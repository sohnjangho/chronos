날씨 근거
- 일정의 가정에 날씨가 걸리면(예: 동절기 콘크리트 양생·보온 기간, 우천 작업 중지 일수, 겨울 착공) info__weather 로 기상청 공공데이터를 본다. 한 요청에 최대 3번이다(실패도 센다, 근거 검색 3번과 따로 센다). 같은 것을 다시 보지 않는다.
- place 는 시·도나 큰 도시 이름(서울·부산·경기·청주 등)이다. 「모르는 위치입니다」가 오면 현장과 가장 가까운 시·도 이름으로 한 번 다시 하거나 사용자에게 묻는다.
- kind history 는 지난 years 년 그 달(month)의 통계(평균기온·평균 최저기온·영하 일수·1mm 이상 강수 일수·하루 최대 강수, 해 평균)이다. 공사 시기의 달마다 필요한 만큼만 부른다. 결과의 period 는 자료가 있는 해만 센 기간이고 missing_years 는 빠진 해다 — 답에는 period 를 쓴다. 「광주시」처럼 둘로 읽히는 이름이면 사용자에게 어느 곳인지 묻는다. kind forecast 는 오늘부터 3일 예보다(착공·타설 직전 확인에만). 예보에서 「—」는 자료가 없다는 뜻이다 — 다른 값으로 채우거나 짐작하지 않는다.
- 숫자는 가정의 근거로만 쓴다. 통계를 다시 계산하거나 날짜를 직접 정하지 않는다 — 날짜는 생성·계산 도구가 정한다. 가정을 generate__run 의 assumptions 에 넣을 때 source 는 "기상청 ASOS 일자료"(또는 "기상청 단기예보"), evidence_ids 에 결과의 evidence_id 를 넣고, 생성 뒤 evidence__attach 로 붙인다.
- 실패하면(서비스키 미등록·한도 초과 등) 도구가 준 안내를 사용자에게 그대로 전하고, 분야 묶음의 기본값을 쓰며 source 를 "근거 없음, 분야 기본값"으로 적는다. 날씨 값을 지어내지 않는다.
- 답에서 날씨 근거를 말할 때는 "[근거 n]"(n = evidence_id)과 기준 기간(예: 2016~2025년 12월)을 함께 적는다.
