# 연락처 프로그램과 문자·카카오톡·AI 전화 설계 (2026-11-23, 2판)

상태: PM 승인 대기 · 화면 시안 https://claude.ai/artifact/Wn8a1mbMf3mPTzZ88dBgtQ (`docs/design/mockups/outreach-mockups.html`)

## 왜
지금은 현장 사람이 앱을 열어야만 요청을 본다. 협력사 담당자에게 문자·카카오톡·전화로 직접 닿게 하고, 주고받은 것을 일정과 함께 남긴다.

## PM 이 정한 것 (11-23)
- 시간보다 품질. 문자·카카오톡·전화 모두.
- 주소록은 협력사별이고 **프로젝트별로 격리**해 저장한다. 사람마다 **근무시간·성별·언어**를 둔다.
- 시연은 PM 본인 번호로만. 본선에 가면 다른 담당자 연락처를 넣는다.
- 새 프로그램 「연락처」: 왼쪽 주소록(이름·담당), 오른쪽 대화창. 말풍선·날짜 줄. 보낸 사람은 `[로그인한 이름 발신]` / `[에이전트 발신]`. 문자와 카카오톡은 한 대화, 입력창에서 고름. 통화는 위 탭.
- 연결 설정은 「LLM 연결」과 같은 꼴.
- 전화는 한국AI통신 **음성 에이전트 개발도구(SDK)** 로 우리 서버에서 돌린다 — 통화 중 예상 밖 상황에 대응하도록. 음성 모델은 **구글(Gemini Live) 무료 키로 시작**하고 키는 설정에서 넣는다.
- 통화 상황(담당자가 아님 → 담당자를 묻고, 주소록에 있으면 그 사람에게, 없으면 연락처를 받음 등)을 **하네스**로 구현한다.
- 에이전트에게 **발송 권한을 위임할지 승인받을지**를 설정에서 고른다.
- 전화는 **상대 성별과 반대되는 성별의 음성**으로 건다. 음성은 PM 이 샘플을 듣고 고른다.
- **여러 언어**로 전화할 수 있게 한다.
- 한국AI통신과는 **API**(문자·카카오톡은 REST, 전화는 SDK)로 붙는다. MCP 는 쓰지 않는다.
- **걸려 온 전화도 에이전트가 받아** 일정 물음에 답하게 한다.

## 목표 / 하지 않는 것
- 목표: 프로젝트별 주소록, 한 사람과의 문자·카카오톡 대화와 통화 기록, 에이전트 초안과 (설정에 따른) 위임 발송, 통화 하네스, 결과 기록(도착·실패·회신·받아쓰기·요약), 시험 모드.
- 하지 않는 것: 광고성 메시지, MMS, 050 안심번호, 웹훅 수신(공개 주소가 없음 — 주기적 조회와 SDK 이벤트로 대신), 대량 캠페인, 통화 중 일정 변경·승인.
- 실패로 보는 것: 허용하지 않은 번호로 실제 발송·발신, 근무시간 밖 전화, 다른 프로젝트 연락처가 보이거나 에이전트에게 읽힘, 키·전화번호가 모델·기록·로그에 그대로 남음, 같은 메시지 두 번 발송, 받아쓰기에 근거가 없는 통화 결과가 사실처럼 기록됨.

## 접근
- 화면: 메신저 꼴 프로그램(PM 선택). 일정·현장 화면에서 시작하는 길은 이 프로그램의 대화로 이어진다.
- 문자·카카오톡 결과: 웹훅 대신 주기적 조회.
- 전화 — 세 방식을 견줌:
  - 대시보드 음성 에이전트(플랫폼이 실행, 키 불필요): 통화 중 우리 자료를 못 본다 → 키가 없을 때의 대체로만 둔다.
  - **SDK + Gemini Live(PM 선택)**: 우리 서버에서 돌고(나가는 연결만), 통화 중 도구로 주소록·일정을 본다. 무료 등급은 통화 내용이 구글 제품 개선에 쓰이므로 실제 협력사와 통화할 때는 유료 등급으로 바꾼다. 한국AI통신 문서에 「검증 중」이라 실제 계정으로 먼저 확인한다.
  - SDK + OpenAI Realtime(유료, 문서상 검증 완료): 같은 구조에서 키만 바꿔 전환.

## 제공사 (문서 확인분)
- 한국AI통신 REST: `Authorization: Bearer <API Key>`, `https://api.koreaaitel.com/v1/accounts/{accountId}/…` — `POST …/messages`(문자·알림톡·대신 보내기·중복 방지 키), `GET …/messages/{id}`, `GET …/messages?status=received`(회신), `GET …/calls/{id}`, 녹음·받아쓰기·요약 조회.
- 한국AI통신 음성 에이전트 SDK(Python, `pip install "koreaaitel[agent,…]"`): 우리 프로세스가 플랫폼으로 WebSocket 을 연다(터널·공개 주소 불필요). `agent.call(번호)`, `@agent.tool`(우리 프로세스에서 도는 도구), `call.transfer(…)`, `call.hangup()`, 이벤트 `call_start`·`call_end`·`call_failed`·`transcript(role, text)`, 로컬 녹음.
- 음성 모델: `GeminiRealtime`(구글 키) / `OpenAIRealtime`(OpenAI 키).
- 알림톡: 카카오 채널 연결과 문안 검수 승인이 먼저다.
- **실제 계정으로 먼저 확인할 것(첫 단계)**: SDK 가 사설망에서 붙는지, Gemini Live 로 한국어 통화가 되는지·지연, 음성 목록과 샘플 만들기, 도구 호출, 통화 전사 이벤트, 회신 문자 조회, 다른 언어 통화. 안 되는 것이 있으면 OpenAI 키 또는 대시보드 방식으로 내려간다.

## 자료 (모두 일정 = 프로젝트에 묶인다)
- `contact_companies`: 일정, 이름, 공종, 메모.
- `contacts`: 일정, 협력사, 이름, 담당, 전화번호, 받을 수 있는 것(문자·카카오톡·전화), **근무시간**(요일·시작·끝, 비우면 프로젝트 달력 기본값), **성별**(남·여·모름), **언어**(기본 한국어), 음성 고르기(자동=반대 성별 / 직접 지정), 수신 거부, 메모, 숨김.
- `contact_proposals`: 통화에서 받은 새 연락처 제안(이름·담당·번호·어느 통화에서) — 사람이 승인해야 주소록에 들어간다.
- `outreach_messages`: 일정, 연락처, 방향, 채널, 내용(+번역), 문안 id·변수, 시작한 쪽(사람·에이전트)과 이름, 보낸 방식(사람이 보냄·사람이 승인·위임), 상태(초안·예약·접수·도착·실패·시험 모드로 막힘·받음), 실패 까닭, 대신 보낸 문자 여부, 제공사 메시지 id, 중복 방지 키, 연결(작업·현장 항목·승인 건·대화·통화), 묶음 id, 시각.
- `outreach_calls`: 일정, 연락처, 목적, 물어볼 것, 말하지 않을 것, 언어, 음성, 시작한 쪽·보낸 방식, 상태(초안·예약·거는 중·통화됨·받지 않음·통화 중·실패·시험 모드로 막힘·근무시간 밖으로 막힘), 통화 시간, 받아쓰기(화자·시각), 요약(한국어), 질문별 답(+근거 발화), 결과(에이전트 제안 / 사람 확정), 하네스 사건(어떤 규칙이 무엇을 막았나), 앞선 통화(누구에게서 넘어왔나), 시각.
- `notify_connections`: 이름, 공급자, 주소, 키(암호문·끝 4자리), Account ID, 발신번호, 카카오 채널·문안 표, 시험 모드·허용 번호, 하루 상한, **에이전트 발송 권한**(채널별: 승인 받기 / 위임), 상태.
- `voice_settings`(알림 연결에 딸림): 음성 모델 공급자(구글·OpenAI·대시보드), 키(암호문·끝 4자리), 모델, **남성 연락처에게 쓸 음성 / 여성 연락처에게 쓸 음성 / 성별 모름일 때 음성**, 언어별 음성(선택), 최대 통화 시간.

## 지켜야 할 규칙 (코드가 지킨다)
1. **보내기·걸기는 한 함수만 거친다.** 그 함수가 아래를 차례로 본다: 시험 모드·허용 번호 → 수신 거부 → 근무시간 → 하루·사람당 상한 → 권한(사람이 눌렀나 / 위임인가) → 중복.
2. **권한**: 채널별 설정이 「승인 받기」면 에이전트는 초안만 만들고 사람이 [보내기]·[전화 걸기]를 눌러야 나간다. 「위임」이면 에이전트가 직접 보내되 1의 나머지 검사는 그대로 받고, 기록에 `[에이전트 발신 · 위임]`으로 남는다. 기본은 모두 「승인 받기」.
3. **근무시간 밖**: 전화는 걸지 않는다(예약만). 문자·카카오톡은 다음 근무 시작 시각으로 예약한다.
4. **시험 모드**(기본 켜짐): 허용 번호가 아니면 제공사를 부르지 않고 기록만 남긴다. 통화 중 전환·후속 통화에도 같다.
5. **프로젝트 격리**: 모든 조회·쓰기·통화 중 도구는 그 일정의 주소록만 본다.
6. **전화번호는 모델에게 주지 않는다.** 글 에이전트도 음성 에이전트도 연락처 id·이름·담당·협력사만 본다. 번호는 코드가 붙인다. 화면은 가운데를 가리고 눌러서 본다.
7. **키**(한국AI통신·구글·OpenAI)는 암호화 저장·끝 4자리만 표시, 응답·오류·로그·trace 에서 지운다.
8. **중복 방지**: 메시지마다 고유 키. 같은 목적의 통화가 진행 중이면 또 걸지 않는다. 받지 않은 전화는 자동으로 다시 걸지 않는다(위임이어도 한 번까지, 다음 근무 시간대에).
9. 제공사를 부르는 동안 DB 쓰기를 쥐지 않는다.

## 연락 하네스 — 문자·카카오톡·통화에 하나로 (PM 추가 11-23)
채널마다 따로 두지 않는다. **하네스는 하나**이고 문자·카카오톡·통화는 그 위에 얹는 통로다. 아래 통화·문자 절의 규칙과 시나리오(V·R·T)는 이 하네스의 채널별 모습이다.

**한 벌로 두는 것(코드 모듈 하나씩):**
1. **나가는 문**: 보내기·걸기는 채널과 상관없이 같은 검사를 같은 차례로 받는다 — 시험 모드·허용 번호 → 차단·수신 거부 → 근무시간 → 상한 → 권한(사람이 누름 / 위임) → 중복. 채널은 마지막에 고른다(카카오톡 문안이 승인 전이면 문자로).
2. **들어오는 문**: 번호로 발신자 등급을 정한다(등급표는 하나). 전화든 문자든 같은 등급, 같은 받기·거절 규칙, 같은 되풀이 상한.
3. **도구 묶음**: 음성 에이전트와 글 에이전트가 **같은 도구**(`find_contact`·`propose_contact`·`schedule_fact`·`my_requests`·`record_answer`·`take_message`·`report_from_contact`·`schedule_callback`·`mark_do_not_contact`·`handoff_to_human`)를 등급별로 받는다. 도구마다 범위를 다시 본다. 통화에만 있는 것은 `end_call`·전환뿐.
4. **신원 규칙**: 말이나 글로 한 신원 주장은 등급을 올리지 않는다 → 등록된 번호로 회신.
5. **바꾸지 않는다**: 어느 채널로 들어와도 일정·승인은 바뀌지 않는다. 보고·요청으로 기록해 사람이 확인한다.
6. **기록**: 메시지와 통화가 같은 하네스 사건 형식(어느 규칙이 무엇을 막았나·허용했나, 근거)을 남긴다. 「연락처」의 한 사람 대화에 채널 표시만 달리해 함께 보인다.
7. **뒤 확인**: 에이전트가 말하거나 쓴 사실마다 도구 결과에 근거가 있는지, 범위 밖 내용이 나갔는지 본다(통화는 받아쓰기, 문자는 보낸 글).

## 통화 하네스
**첫마디는 코드가 정한다**(언어별 고정 문장): 「안녕하세요, {현장} 일정 담당 ChronOS AI 비서입니다. 이 통화는 기록됩니다. {이름}님 맞으신가요?」

**통화 중 음성 에이전트가 쓸 수 있는 도구는 이것뿐이다:**
- `confirm_person(맞음/아님)` · `find_contact(이름 또는 담당)`(이 프로젝트만, 번호 없음) · `propose_contact(이름, 담당, 번호)`(제안으로만 저장) · `record_answer(질문, 답, 들은 말)` · `schedule_callback(언제)`(초안·예약) · `mark_do_not_contact(까닭)` · `schedule_fact(작업)`(이름·날짜 같은 허용된 사실만) · `handoff_to_human(까닭)` · `end_call(까닭)`.
- 없는 것: 일정 바꾸기, 승인, 금액·계약 조회, 다른 프로젝트 조회.

**통화 뒤 코드가 확인한다:** 질문별 답마다 받아쓰기에 근거 발화가 있는지(없으면 「확인 필요」), 통화 시간·상태, 새 연락처는 제안으로, 후속 행동은 권한 설정대로(초안 또는 위임 실행).

**시나리오(하네스 시험 목록)** — 자동 시험은 실제 통화 없이 대본으로 돌리고, 개발 콘솔 하네스 탭에도 넣는다:

## 걸려 온 전화 받기 (PM 추가 11-23)
우리 070 번호로 전화가 오면 음성 에이전트가 받아 일정에 관한 물음에 답한다. SDK 가 걸려 온 통화를 받는다(번호를 우리 에이전트에 묶는 방법은 0단계에서 확인).

- **누구인지**: 건 번호를 주소록에서 찾는다(번호는 코드가 견주고 모델에게 주지 않는다).
  - 한 프로젝트의 연락처 → 그 프로젝트 맥락으로 응대.
  - 여러 프로젝트에 있음 → 어느 현장 일인지 먼저 묻는다.
  - 주소록에 없음·번호 표시 제한 → 일정 내용은 말하지 않는다. 용건·이름·연락처만 받아 메모로 남기고 새 연락처 제안을 만든다.
- **말해도 되는 것**: 그 사람 협력사·공종의 작업 이름과 날짜, 프로젝트 주요 마일스톤 날짜, 본인에게 온 요청(체크인·핸드오프)의 내용. 발신 번호는 속일 수 있으므로 그 이상은 말하지 않는다.
- **말하지 않는 것**: 금액·계약, 다른 협력사의 사정, 다른 프로젝트, 내부 평가·만회안 검토 내용.
- **전화로는 아무것도 바꾸지 않는다.** 지연·문제 보고와 일정 변경 요청은 「전화로 받은 보고」로 기록해 사람이 확인하게 올린다(지연 사건·일정 변경을 바로 만들지 않는다).
- **받는 범위(설정)**: `받지 않음`(기본) / `주소록에 있는 번호만` / `모두 받기`(모르는 번호는 메모만). 시험 모드에서는 허용 번호만 받고 나머지는 받지 않는다.
- **받을 수 없을 때**(앱이 꺼짐·통화 중 한도): 받지 않는다. 부재중 통화로 기록하고, 권한 설정에 따라 회신 문자 초안을 만든다.
- **음성·언어**: 건 사람의 성별·언어가 주소록에 있으면 거는 통화와 같은 규칙(반대 성별 음성, 그 사람 언어). 모르면 기본 음성·한국어로 받고 상대 언어에 맞춘다.
- **기록**: 통화 탭에 `[상대 발신]`으로 남긴다(받아쓰기·요약·물은 것과 답한 것·하네스 사건). 주소록에 없는 사람의 통화는 「모르는 번호」 묶음에 모은다.
- **통화 중 도구**: 거는 통화의 도구에 더해 `my_requests()`(이 사람에게 온 요청), `take_message(내용)`, `report_from_call(종류, 내용, 들은 말)`.

### 번호 기반 응대 하네스 (PM 추가 11-23)
걸려 온 번호로 **코드가** 발신자 등급을 정하고, 등급마다 받을지·무엇을 말할 수 있는지·어떤 도구를 줄지를 정한다. 음성 에이전트는 등급을 바꿀 수 없다.

| 등급 | 번호가 어떤가 | 받기 | 줄 도구 | 말할 수 있는 범위 |
|---|---|---|---|---|
| 내부 | 로그인 계정(관리자·사용자)에 등록된 번호 | 받음 | 연락처 도구 + `schedule_fact` | 그 계정이 볼 수 있는 프로젝트의 작업 이름·날짜·상태 |
| 연락처(한 프로젝트) | 주소록 한 곳에 있음 | 받음 | `schedule_fact`·`my_requests`·`take_message`·`report_from_call`·`find_contact` | 그 협력사·공종의 작업, 주요 마일스톤, 본인에게 온 요청 |
| 연락처(여러 프로젝트) | 주소록 여러 곳에 있음 | 받음 | 위와 같음 — 현장을 고른 뒤에만 `schedule_fact` 가 답함 | 고른 현장에 한해 위와 같음 |
| 같은 번호 여러 사람 | 한 번호가 두 사람 이상(회사 대표번호) | 받음 | 위와 같음 | 그 협력사 범위까지만(개인에게 온 요청은 말하지 않음) |
| 수신 거부 | 수신 거부 표시된 연락처 | 받음 | `take_message`·`end_call` | 일정은 말하지 않음. 우리가 먼저 거는 것은 계속 막음 |
| 모르는 번호 | 어디에도 없음 | 설정이 `모두 받기`일 때만 | `take_message`·`propose_contact`·`end_call` | 일정 내용 없음 |
| 번호 표시 제한 | 번호가 오지 않음 | 모르는 번호와 같음 | 같음 | 같음 |
| 차단 | 관리자가 차단한 번호, 짧은 시간에 여러 번 건 번호 | **받지 않음**(받기 전에 거절 — 통화료 없음) | — | — |
| 시험 모드 밖 | 시험 모드인데 허용 번호가 아님 | **받지 않음** | — | — |

**지키는 곳(네 겹):**
1. **받기 전**: 등급을 정하고 거절할 것은 받지 않는다. 받지 않은 통화도 기록한다.
2. **통화를 만들 때**: 그 등급의 도구만 넣는다 — 없는 도구는 부를 수 없다. 첫마디·최대 통화 시간·음성·언어도 등급과 주소록에서 정한다.
3. **도구가 불릴 때마다**: 도구가 등급과 범위를 다시 본다. `schedule_fact` 는 범위 밖 작업이면 「말씀드릴 수 없는 내용입니다」를 돌려준다(모델이 우겨도 자료가 가지 않는다).
4. **통화 뒤**: 답한 것마다 근거(도구 결과)가 있는지, 범위 밖 내용이 말해졌는지 받아쓰기를 훑어 하네스 사건으로 남긴다.

**말로 한 신원 주장은 등급을 올리지 않는다.** 모르는 번호에서 「저 박현장인데 다른 전화로 걸었습니다」라고 하면: 일정은 말하지 않고, **등록된 번호로 다시 전화드리겠다**고 안내한 뒤 그 번호로 거는 통화 초안을 만든다(권한 설정대로). 주소록 번호로 걸려 와도 발신 번호는 속일 수 있으므로, 위 표의 범위를 넘는 것(변경 요청의 확정 등)은 전화로 처리하지 않는다.

**받는 통화 시나리오에 더하는 것:** R-13 모르는 번호가 주소록 사람이라고 주장 → 등급 그대로·등록 번호로 회신 초안 / R-14 수신 거부 번호가 걸어옴 → 메모만 / R-15 같은 번호가 10분에 5번 → 이후 거절 / R-16 내부 계정 번호 → 내부 범위 / R-17 회사 대표번호(여러 사람) → 협력사 범위까지만 / R-18 범위 밖 작업을 캐물음 → 도구가 거절, 사건 기록.

## 들어온 문자에 답하기 (PM 추가 11-23)
우리 070 번호로 온 문자도 걸려 온 전화와 **같은 번호 기반 하네스**로 다룬다(등급표·네 겹·신원 주장 규칙 그대로).

- 들어온 문자는 주기적 조회로 받아 그 사람의 대화에 왼쪽 말풍선으로 넣는다. 주소록에 없는 번호는 「모르는 번호」 묶음에.
- 글 에이전트가 등급에 맞는 도구만 가지고 답 초안을 만든다. 나가는 것은 문자 채널의 권한 설정대로: 「승인 받기」면 점선 말풍선 초안, 「위임」이면 바로 보낸다(`[에이전트 발신 · 위임]`).
- 등급별: 연락처는 허용된 범위의 사실로 답한다. 모르는 번호·번호 표시 제한은 일정 내용 없이 「담당자가 확인 후 연락드리겠습니다」 한 번만(하루 한 번). 수신 거부 번호는 답하지 않고 기록만. 차단·시험 모드 밖은 기록만.
- 「비 와서 이틀 밀립니다」 같은 보고·변경 요청은 「문자로 받은 보고」로 기록해 사람이 확인한다. 문자로는 아무것도 바꾸지 않는다.
- 우리가 보낸 요청(체크인 등)에 대한 답이면 그 요청에 이어 붙이고, 현장 항목의 회신 후보로 올린다(사람 확인).
- 「수신거부」「그만」 같은 말이 오면 수신 거부로 표시하고 확인 문자 한 번만 보낸다.
- **되풀이 막기**: 한 사람에게 자동 답은 한 시간에 5번·하루 20번까지, 같은 내용 두 번 금지, 자동 발신 문자(인증번호·광고)로 보이면 답하지 않는다.
- 근무시간: 상대가 먼저 보낸 뒤 30분 안의 답은 근무시간 밖이어도 보낸다. 그 밖에는 예약.
- **카카오톡으로 들어오는 것은 받을 수 없다.** 알림톡은 보내기만 되는 길이고, 한국AI통신 문서에도 받는 것은 문자뿐이다. 알림톡 문안에 「답은 이 번호로 문자 주세요」를 넣어 문자로 받는다.

**들어온 문자 시나리오(하네스 시험)**: T-01 연락처가 자기 작업 날짜를 물음 → 허용된 사실로 답 / T-02 모르는 번호가 일정을 물음 → 일정 없이 안내 한 번 / T-03 지연·문제 보고 → 보고로 기록 / T-04 체크인 요청에 대한 답 → 그 요청에 이어 붙임 / T-05 「수신거부」 → 표시·확인 한 번 / T-06 모르는 번호의 신원 주장 → 등급 그대로·등록 번호로 회신 / T-07 광고·인증번호 문자 → 답하지 않음 / T-08 1분에 문자 10통 → 상한에서 멈춤 / T-09 다른 언어 → 그 언어로 답 / T-10 범위 밖 작업을 물음 → 도구가 거절 / T-11 「승인 받기」 설정 → 초안만 / T-12 사진이 붙은 문자 → 기록만(판독하지 않음).

## 카카오톡이 붙는 방식
- 쓰는 것은 **알림톡**(정보성 알림, 보내기만)이다. 준비 차례: ① 카카오톡 채널(비즈니스 채널)을 만든다 → ② 한국AI통신 콘솔에서 채널을 연결한다(채널 검색용 ID + 채널 관리자 휴대전화로 온 인증번호) → ③ 알림톡 문안을 등록하고 카카오 검수를 받는다(승인 전에는 못 보냄) → ④ 승인된 문안의 번호를 우리 설정의 문안 표에 잇는다.
- 보낼 때는 문자와 같은 API 에 채널·문안·변수를 넣는다. 본문은 문안대로만 나가고 바꿀 수 있는 것은 변수뿐이다. 실패하면(카카오톡 미사용 등) 문자로 대신 나간다.
- 채널·문안이 준비되기 전에는 카카오톡을 고를 수 없고 문자로만 나간다. 우리 앱은 연결된 채널과 문안의 승인 상태를 읽어 설정에 보인다.
- 확인 필요: 알림톡용 채널은 카카오 정책상 사업자 인증이 필요할 수 있다(한국AI통신 문서에는 요건이 적혀 있지 않음). PM 이 채널을 만들 수 있는지 먼저 확인한다.

## 음성과 언어
- 설정에서 음성 목록을 불러와 **샘플을 듣고** 고른다: 「남성 연락처에게 걸 때」「여성 연락처에게 걸 때」「성별 모름」 세 칸. 샘플은 고른 언어의 한 문장으로 만들어 서버에 보관한다(다시 들을 때 호출하지 않게).
- 전화를 걸 때 연락처의 성별로 음성을 고른다(남 → 여성 음성 칸, 여 → 남성 음성 칸). 연락처에서 직접 지정하면 그것이 우선.
- 연락처의 언어로 통화한다(첫마디·지시문·질문). 받아쓰기는 원문 그대로, 요약은 한국어로 붙인다. 문자도 그 언어로 쓰고 말풍선 아래에 한국어 번역을 보인다.

## 「연락처」 프로그램
- 왼쪽: 찾기, 협력사별 묶음, 사람 줄(이름·담당·새 회신 수·번호 없음·수신 거부 표시). 아래에 사람 추가·협력사 추가·CSV 가져오기·다른 프로젝트에서 복사해 오기(관리자).
- 오른쪽 머리: 이름·담당·협력사, 가린 번호, 근무시간(지금 근무 중인지), 언어, 탭 `문자 · 카카오톡` | `통화 n`.
- 문자·카카오톡 탭: 날짜 줄, 말풍선, `[이름 발신]` / `[에이전트 발신] · 승인한 사람` / `[에이전트 발신 · 위임]`, 채널·시각·상태(도착·실패 → 문자로 대신 보냄·예약됨·시험 모드로 보내지 않음), 연결된 작업. 에이전트 초안은 점선 말풍선 + [버리기][고치기][보내기].
- 입력창: `문자 | 카카오톡`, 연결할 작업, 글자 수, [에이전트에게 초안 맡기기], [보내기]. 카카오톡은 승인된 문안 고르기 + 변수.
- 통화 탭: 날짜 줄, 통화 카드(상태·시간·요약·질문별 답과 근거·하네스 사건·[받아쓰기][녹음][결과 확정]·[다시 걸기]). [전화 걸기] → 목적·물어볼 것·말하지 않을 것·언어·음성 확인 창.
- 새 연락처 제안이 있으면 주소록 위에 「확인할 연락처 n」.
- 권한: 관리자·사용자. 현장 관리자는 열 수 없다.
- 태블릿은 같은 두 칸, 스마트폰은 목록 → 대화 한 화면씩(아래 탭에 「연락처」).

## 다른 화면에서 시작하기
스케줄·간트 작업 행 [연락] · 현장 허브의 체크인·의견 조회·핸드오프 발송 · 승인함의 승인권자 알림 · 대화에서 에이전트에게 요청.

## 글 에이전트 도구
`contacts.list` · `notify.draft_message` · `notify.draft_call` · `notify.status` · (채널이 위임일 때만) `notify.send_message` · `notify.place_call`.

## 설정 「알림 연결」 (LLM 연결과 같은 꼴)
- 카드: 이름·공급자·상태·주소·키 끝 4자리·확인 시각, [연결 테스트][주소 수정][키 교체][삭제].
- 아래 칸: Account ID, 발신번호, 카카오 채널·문안 표, 시험 모드·허용 번호, 하루 상한, **에이전트 발송 권한**(문자 / 카카오톡 / 전화 각각 `승인 받기 | 위임`).
- 「AI 전화」 묶음: 음성 모델 공급자(구글 Gemini Live · OpenAI Realtime · 대시보드 에이전트), 키 넣기·[연결 테스트], 음성 세 칸(▶ 샘플 듣기), 최대 통화 시간, [시험 전화](허용 번호로).

## 만드는 차례
0. **확인 단계**: PM 계정·키로 SDK+Gemini 통화가 되는지, 음성·언어·도구·전사 이벤트를 작은 시험으로 확인. 결과에 따라 음성 방식 확정.
1. 서버 뼈대: 표, 알림 연결, 제공사 호출, 보내기 함수(규칙 1~9), 상태·회신 조회 일꾼.
2. 「연락처」 프로그램: 주소록(근무시간·성별·언어), 문자 대화, 입력창.
3. 글 에이전트 도구·초안·위임, 대화 카드.
4. 통화: 음성 일꾼(SDK), 하네스 도구, 걸기 창, 통화 탭, 받아쓰기·요약·근거 대조.
5. 통화 하네스 시험(V-01~17, 받는 통화 R-01~12)과 개발 콘솔 항목. 걸려 온 전화 받기.
6. 음성 고르기·샘플, 여러 언어.
7. 카카오톡: 문안 표, 고르기, 대신 보내기 표시.
8. 다른 화면에서 시작하기, 태블릿·스마트폰 화면.
단계마다 검토하고, 실제 발송·통화 확인은 PM 번호로만 한다.

## PM 이 준비할 것
한국AI통신 가입·070 번호·API Key·Account ID, 구글 AI Studio 무료 키, 카카오톡 채널 연결과 문안 검수 신청(문안 초안은 따로 드림).

## 내가 정한 것 (PM 이 다르게 원하면 고친다)
- V-01 의 「연결」은 처음 받은 사람과 담당자를 이어 주는 전환이 아니라, 담당자에게 **새로 거는 통화**다.
- 위임은 채널별(문자·카카오톡·전화)로만 나눈다. 메시지 종류별로는 나누지 않는다.
- 다른 프로젝트의 연락처는 관리자가 「복사해 오기」로 가져온다(복사 뒤에는 따로 고친다).
- 스마트폰 아래 탭은 「자료함」 자리에 「연락처」를 넣고 자료함은 「전체」 안으로.
- 받지 않은 전화의 자동 재발신은 위임이어도 한 번까지.
