## 0. 한 장 요약

> **공정이 늦어서가 아니라, 약속을 정하는 줄이 옮겨 간 걸 늦게 알아서 약속을 놓친다.**

〔대표 화면: 「관리 포인트가 바뀌었습니다」 카드〕

같은 3일 지연이라도 여유가 있는 작업이면 준공에 아무 일이 없고 약속을 정하는 줄(크리티컬 패스)에 있으면 준공이 늦어진다. 변동이 쌓이면 그 줄이 다른 곳으로 옮겨 간다. 15년차 PM은 변동이 생길 때마다 "지금 약속을 정하는 줄이 어디인가"를 다시 보고 당기기 전에 효과를 따지고, 담당자에게 먼저 묻는다. ChronOS 는 이 노하우를 에이전트로 옮겨 변동이 들어올 때마다 쉬지 않고 실행한다.

> **CPM 이 "어디를 지켜봐야 하는지"를 정하고, Liner 가 "그곳에 무슨 일이 생길지"를 근거와 함께 찾아온다.**

## 1. EXPERIENCE: 경험에서 시작한 문제 (문제 정의 30%)

### 1-1. 현장에서 겪은 장면

> 골조가 크리티컬이었다. 야간 작업까지 넣어 골조를 앞당겨 끝냈다.
> 그런데 다음 외장 작업을 시작할 수 없었다. 그사이 커튼월 공장 제작이 늦어져 약속을 정하는 줄은 이미 커튼월 쪽으로 옮겨 가 있었다.
> 골조를 당기느라 쓴 돈과 사람은 준공을 하루도 당기지 못했다.

4,200억~3조 원 규모의 건설·플랜트 현장에서 15년 동안 일정을 맡으며 가장 자주 본 실패가 이것이다. 몰라서 생긴 실패가 아니었다. 줄이 옮겨 간 것을 늦게 알아서 생겼다.

### 1-2. 누가, 언제, 얼마나 불편한가

| 누가 | 언제 | 얼마나 |
|---|---|---|
| 공정 담당 | 지연·자재·장비 소식이 들어올 때마다 | 공정표를 손으로 다시 맞춘다. 반영은 주간 공정회의 때 몰아서 한다 〔PM 확인: 주기·소요 시간〕 |
| PM | 만회 계획을 정할 때 | 마지막으로 본 크리티컬을 당긴다. 줄이 옮겨 갔으면 야간 작업·장비 추가 비용이 준공을 당기지 못한다 〔PM 확인: 야간 작업 하루 비용 예〕 |
| 현장 관리자 | 협력사 일정을 확인할 때 | 전화를 돌리고 통화 내용은 남지 않는다 〔PM 확인: 하루 확인 전화 수·시간〕 |
| 발주처와 약속 | 준공이 늦어질 때 | 공공 공사의 지체상금은 하루에 계약금액의 1천분의 0.5다(국가계약법 시행규칙 제75조). 300억 원 공사면 하루 1,500만 원 |

### 1-3. 왜 되풀이되나

같은 네트워크에 같은 3일 지연 두 건을 넣어 보면 차이가 보인다. 크기가 아니라 위치가 약속을 늦춘다.

〔그림: 왼쪽은 여유에 흡수되고 오른쪽은 약속을 정하는 줄이 바뀐다〕

| 놓치는 까닭 | 사람 | 전문 공정 도구(P6 등) | 엑셀 | 범용 AI 챗봇 |
|---|---|---|---|---|
| 변동마다 전체를 다시 계산 | 못 함(주간 회의 때 몰아서) | 함 | 못 함 | 날짜를 틀림 |
| 줄이 옮겨 간 것을 알림 | 처음 본 크리티컬을 계속 봄 | 알려 주지 않음 | 없음 | 없음 |
| 그곳의 바깥 위험(자재값·환율·업체) | 담당자 감에 맡김 | 없음 | 없음 | 출처 없이 말함 |
| 담당자에게 확인하고 기록 | 전화, 기록 없음 | 없음 | 없음 | 현장 밖 사람에게 연락 못 함 |

건설만의 문제가 아니다. 생산(설비, 금형, 납기), 연구개발(시험 장비, 인증), 사업화(인허가, 계약)도 약속을 정하는 줄이 옮겨 가는 구조가 같다.

## 2. .EXE: 노하우를 에이전트로 (완성도 30%, Liner API 20%)

### 2-1. 15년차 PM의 노하우 세 가지를 옮겼다

| PM 이 하던 일 | ChronOS 가 하는 일 | 누가 계산·판단하나 |
|---|---|---|
| 변동이 생기면 "지금 약속을 정하는 줄이 어디인가"를 다시 본다 | 변동마다 영향을 재고 관리 포인트(크리티컬 + 여유 3일 이하, 앞으로 3주)를 다시 정해 바뀐 것을 카드로 알린다 | 코드 |
| 힘을 쏟기 전에 "이걸 당기면 준공이 당겨지나"를 따진다 | 「당겨도 소용 있나」: 당긴 일수 대비 준공에 반영되는 일수와 그다음 약속을 정하는 줄을 계산한다 | 코드 |
| 그 작업의 담당자에게 먼저 묻고 들은 것을 근거로 결정한다 | 새 포인트의 바깥 위험을 출처와 함께 찾고 담당자에게 문자·AI 전화로 묻고 답마다 근거 발화를 남긴다. 결정은 승인함에서 사람이 한다 | Liner + 사람 |

### 2-2. 에이전트의 한 바퀴

```
   ┌──────────── ① 변동이 들어온다 ◀───────────────────────────┐
   │   대화 한 줄, 현장 체크인, 사진, 걸려 온 전화와 문자, CSV       │
   ▼                                                             │
 ② 영향을 잰다            코드: CPM, 근무 달력, 자원 (오차 0%)          │
   ▼                                                             │
 ③ 관리 포인트를 다시 정한다  코드: 크리티컬 + 여유 ≤ 3일, 3주 창, 앞 버전과 비교│
   ▼                                                             │
 ④ 새 포인트의 바깥 위험    Liner Search: 자재 시세와 환율(Premium Data),  │
   ▼                       업종 소식(MCP), 출처 문장(Search Agent)       │
 ⑤ 담당자에게 확인한다      Liner Model 글 + AI 전화, 연락 하네스         │
   ▼                                                             │
 ⑥ 대안을 견주고 결정한다   「당겨도 소용 있나」(코드), 만회안, 승인함(사람) │
   ▼                                                             │
 ⑦ 새 버전 → 관리 포인트 다시 계산 ──────────────────────────────────┘
```

| 누가 | 하는 일 | 하지 않는 일 |
|---|---|---|
| 코드 | 날짜, 여유, 자원, 영향, 관리 포인트, 당김 효과 계산과 4겹 하네스 점검 | 판단 |
| Liner | 요청 해석, 볼 바깥 자료 고르기, 출처 있는 검색과 문장, 연락 글과 통화 요약, 만회안 설명, 보고서와 차트 | 날짜 계산, 숫자 지어내기 |
| 사람 | 승인과 거부, 조건 확정, 연락 보내기(기본값) | - |

### 2-3. Liner Model 과 Liner Search 를 어디에, 왜

| | 맡긴 일 | 알맞은 까닭 | 실측 |
|---|---|---|---|
| **Liner Model** (Router: cost / balanced / quality, `liner-mark`, 사진 vision) | 요청 해석, 질문지, 일정 초안과 고침, 만회안 설명, 연락 글과 통화 요약, 보고서, 사진 판독 | 판단과 글은 모델이 잘한다. 감시처럼 자주 도는 일은 cost, 만회안처럼 무거운 판단은 quality 로 나눠 상시 운영 비용을 줄인다 | 22/22회 정상(도구 호출, strict JSON, 라우팅) |
| **Liner Search** (web·scholar, Premium Data, Search Agent, MCP `search_legal`·`search_business`) | 새 관리 포인트에만 겨냥한 바깥 위험(자재 시세, 환율, 업종 소식), 근거가 된 출처 문장, 법령과 기준 근거 | 약속을 바꾸는 결정에는 출처가 있어야 한다. 포인트에만 찾으니 호출이 적다 | Premium Data: 구리·알루미늄·철광석 30개월과 원·달러(11-24), Search Agent 출처 문장 수신, MCP 5/5회 |
| 그 밖 (Liner 플랫폼) | Visualization(보고서 차트, 그림 속 숫자를 코드가 표와 전수 대조), Embeddings(자료함 뜻 검색) | 숫자는 코드가 다시 확인한다 | 2/2회(15/15 일치), 1536차원 |

> **Liner 가 아닌 것(밝혀 둠)**: 날짜 계산은 코드, 날씨 숫자는 기상청 공공데이터, 실시간 통화 음성은 Google Gemini Live(지연 시간 때문), 문자와 전화 통로는 한국AI통신이다.

## 3. IMPACT: 실제로 도는 시연 (완성도 30%)

### 3-1. 같은 3일, 다른 영향

시연 일정은 「5층 사무동 신축」(가상)이다. 6월 말 실적과 커튼월·창호 조달 일정이 들어간 승인된 새 계획에서 출발한다(준공 2027-11-08, 계획 대비 편차 0). 관리 포인트는 5층 거푸집, 5층 타설, 옥탑 골조(크리티컬)와 4층 거푸집, 4층 타설, 5층 철근(여유 3일)이다. 숫자는 모두 엔진이 계산했고 자동 시험이 고정한다. 오른쪽 칸은 그 장면에서 보이는 신뢰 장치다.

| 7 | 쌓이는 지식 | 월간 보고서(회사 양식 학습), 자료함, 내 규칙, 스킬 〔화면〕 | 보고서 표 숫자는 코드 값, 차트 숫자는 전수 대조 |

### 3-4. 검증

서버 시험 〔갱신〕건, 화면 시험 〔갱신〕건 통과. 실제 Liner 로 46단계 업무 시나리오를 재검증했고 시연 장면은 실제 Liner 로 두 번 리허설했다. 실제 통화 시험은 첫 응답 약 1.1초, 받아쓰기와 도구 호출, 걸려 온 전화 받기까지 통과했다. 사진 판독은 공개 라이선스 현장 사진 10장으로 두 모델을 견줘 숫자를 지어내지 않는 쪽을 골랐다.

## 부록 A. 기술 구조 (개발자 심사용)

- **결정론적 일정 엔진** `backend/app/core/`
  - `calendar.py` 근무일 서수 배열과 이분 탐색으로 공휴일과 금지 기간을 반영해 날짜를 계산한다.
  - `cpm.py` 위상 정렬로 순환을 막고 FS/SS/FF/SF + lag, SNET/FNLT, Data Date 기준 전진·후진 패스로 ES/EF/LS/LF와 TF/FF를 낸다.
  - `resources.py` (ES, TF, id) 우선순위로 일일 용량을 넘지 않는 시작 자리를 찾아 후행으로 전파한다.
  - `shorten.py` 병행, 압축, 자원 추가를 한 수씩 넣고 다시 계산하며 옮겨 가는 크리티컬 패스를 추적해 만회안 묶음을 만든다.
  - `delay.py` 지연 전후 크리티컬을 비교해 새로 크리티컬이 된 작업, 빠진 작업, 새 자원 겹침을 낸다.
  - `points.py` 관리 포인트와 버전 사이 차이, `accel.py` 당김 효과(당긴 일수 대비 준공 반영, 다음 결정 줄). 〔갱신: 계획 5 최종 이름〕
- **4겹 하네스** `backend/app/harness/`: 기본 < 분야 < 내 규칙 < 입력 우선순위로 경합을 판정하고 자동 점검이 안 되는 조건은 따로 표시한다.
- **에이전트** `backend/app/agent/`: ReAct 루프(단계 한도 설정), 도구 실행 전 커밋과 실패 시 되돌림, 자가 점검, 화면과 요청에 맞춘 지침 선택, 스킬 매칭. 도구는 40여 개다.
- **연락** `backend/app/outreach/`, `notify/`: 나가는 문(시험 모드 → 차단 → 근무시간 → 상한 → 권한 → 중복), 들어오는 문(번호로 등급), 통화 하네스(코드가 정한 첫마디, 도구 범위, 받아쓰기와 도구 결과 대조).
- **화면** `frontend/src/os/`, `programs/`: React OS 셸, 앱 18개, PC·태블릿·폰 셸.
