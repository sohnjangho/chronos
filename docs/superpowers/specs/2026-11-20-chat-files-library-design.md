# 대화 첨부 · 자료함(벡터 검색) · 모델 고르기 · 정보 API — 설계 (계획 3 후보)

작성 2026-11-20 · 상태: PM 답 반영(빌더 점검 뒤) · 마감 2026-11-25 23:59 · **범위: 전부 만든다(뺄 순서 없음) [PM]**

> **PM 원칙(11-20):** 판단은 에이전트가 한다 — "코드로 정하는 규칙이면 의미가 없다". 공정표인지 아닌지, 빈 칸을 물을지 추정할지, 분류 값은 에이전트가 판단한다. 날짜·여유·통계 **계산**만 코드가 한다(기존 원칙).

## 1. 왜 하는가
PM 이 지금 대화창을 Claude 채팅과 비교했을 때 빠진 것이 둘이다: **모델을 고를 수 없고, 파일을 붙일 수 없다.**
여기에 더해 PM 은 붙인 파일이 **한 번 쓰고 사라지지 않고 회사 자료로 쌓여**, 일반 사용자도 찾기 쉽고 에이전트가 다른 대화에서도 찾아 쓰기를 원한다(「저장소 도구 프로그램, RAG 임베딩」).
그리고 Liner 검색에 날씨 표가 없으므로(실측 11-20, Task 45 뺌) **공공데이터 API(기상청)를 연결해 에이전트 도구로** 쓰게 한다.

성공 모습(시연 기준):
1. 현장 사진·시방서 PDF·기존 엑셀 공정표를 대화에 끌어 놓는다 → 에이전트가 읽고 답하며, 자료함에 「종류·공종·현장·시기·출처」로 분류돼 저장된다.
2. 엑셀 공정표는 "액티비티 120개, 기간 칸 없음 …" 요약 뒤 [일정 초안으로 가져오기] → 빈 곳은 질문지 → 승인함.
3. 다른 날 다른 대화에서 "동절기 타설 기준 있었지?" → 에이전트가 자료함을 뜻으로 찾아 출처 파일과 함께 답한다.
4. "12월 서울 타설 괜찮아?" → 기상청 과거 10년 12월 통계(평균기온·영하일수·강수일수)를 코드가 계산해 근거로 붙인다.
5. 대화창 위에서 모델을 바꾸고, 그림이 붙으면 「그림 읽기」 모델이 답한다.

## 2. 목표 · 하지 않을 것 · 실패로 볼 것
**목표**
- 대화 첨부(그림·CSV·엑셀·PDF·문서), 파일당 50MB · 한 번에 10개 [PM].
- 자료함 프로그램: 붙인 파일을 에이전트가 파악·분류해 **바로 저장, 언제든 고침** [PM]. 분류는 **축 고정 · 값은 에이전트가 늘림** [PM].
- 검색: 벡터 DB 를 따로 둔 뜻 검색 [PM] + 정확한 낱말 검색.
- 보는 범위: **지금은 회사 전체**, 대회 뒤 고도화 때 나눔 [PM]. 에이전트는 **볼 수 있는 파일 전부**를 찾되, 지금 대화에 붙인 파일을 먼저 쓴다 [PM].
- 세션 기억: 한 대화에 붙인 파일은 대화 내내 에이전트가 안다 [PM].
- 공정표 파일은 **먼저 묻고 가져오기**(빈 곳 질문지, 승인함 거침) [PM].
- 모델 고르기(대화마다), LLM 설정에 **「그림 읽기」(비전) 배정**을 더하고 그림이 붙은 턴은 그 모델로 [PM].
- 정보 API 연결 설정 + 에이전트 도구(날씨부터) [PM].

**하지 않을 것(이번)**: 사용자·현장별 보는 범위 나누기, 스캔 PDF 글자 인식(OCR), P6 xer · MS Project xml 가져오기, 옛 hwp·dwg·mpp·zip, 파일 버전 관리, 외부 공유 링크, 날씨 말고 다른 정보 API(연결 틀만 일반으로).

**실패로 볼 것(돌아가도 안 됨)**: LLM 이 날짜·통계를 계산해 넣음(날짜·평균은 코드만) · 키가 로그·응답·자료에 남음 · 붙인 파일을 다음 턴에 잊음 · 에이전트가 읽지 않은 파일 내용을 지어내거나 출처 없이 인용 · 첨부 하나 때문에 대화가 멈춤(읽는 중에도 대화는 된다).

## 3. 제약
- 기존 원칙 그대로: 날짜·여유·통계는 `app/core`·코드만, 키는 Fernet 암호문·끝 4자리, `.env`·`data/` 커밋 금지, 한국어 화면, 화면 검수 5항목, 모듈 경계(프로그램끼리 import 금지), TDD.
- PM 앱은 **Docker 없이 맥에서 직접** 띄운다(`~/projects/chronos-serve`, 재부팅하면 다시 띄움). 벡터 DB 도 맥에서 직접 돌아야 한다.
- 비용: Liner 임베딩(`/api/v1/embeddings`, OpenAI 형식, 예 `openai/text-embedding-3-small`)과 그림 입력 토큰. 비용 관리는 하지 않지만 낭비는 피한다(같은 파일 다시 올리면 다시 임베딩하지 않음).
- 남은 묶음 2 화면 작업(36~42)과 나란히 진행 → 파일 경계를 겹치지 않게.

## 4. 만드는 방법(Approaches)
| | 방법 | 얻는 것 | 잃는 것 |
|---|---|---|---|
| ① | SQLite 안에 조각·임베딩, 뜻 검색 + FTS5 | 서버 추가 없음, 백업 한 폴더 | 아주 커지면 느림 |
| **② 선택 [PM]** | **벡터 DB 를 따로** 두고, 파일 정보·분류는 SQLite | 커져도 빠름, 필터 검색, 나중에 서버로 키우기 쉬움 | 띄울 것이 하나 늘어남 |
| ③ | 임베딩 없이 낱말 검색만 | 가장 쌈 | 뜻 검색 안 됨 — PM 요구와 어긋남 |

**[내 판단] 벡터 DB = Qdrant.** 까닭: 맥용 단일 실행 파일로 Docker 없이 띄울 수 있고, payload 필터(축 값으로 거르기)가 강하며, Python 클라이언트(`qdrant-client`)에 **같은 API 의 내장 모드**(`:memory:`·로컬 폴더)가 있어 시험은 서버 없이 돈다. Chroma 는 기본 설치가 무겁다(onnxruntime 등).
- 운영: `qdrant` 실행 파일을 맥에서 직접 `127.0.0.1:6333`, 자료는 `data/qdrant/`. 설정 `CHRONOS_QDRANT_URL`. **서버가 꺼져 있으면 뜻 검색만 끄고 낱말 검색으로 버틴다**(앱은 뜬다). 꺼진 동안 들어온 파일은 「다시 넣기」 줄에 남기고 서버가 돌아오면 넣는다. 앱 안의 로컬(내장) 모드는 쓰지 않는다(서버와 저장 형식이 달라 갈라짐) — **시험만** 내장 `:memory:` 를 쓴다 **[내 판단, 빌더 질문 4]**. PM 앱 띄우는 방법(README·메모리)에 Qdrant 띄우기를 더함.
- 낱말 검색: SQLite FTS5(글 조각 표) — "C24", "SNET" 같은 정확한 낱말. 결과는 뜻 검색과 합쳐 순위(RRF).

## 5. 정한 것(설계)

### 5-1. 첨부 받기(서버)
- `POST /api/files`(multipart, 여러 개) → 파일마다 `{file_id, name, kind, status}`. 한도 50MB·10개, 넘으면 413/422 한국어 글.
- 원본은 `data/files/<sha256 앞 2자>/<sha256>` — **같은 내용이면 다시 저장·임베딩하지 않고** 기존 파일을 돌려준다(새 대화 연결만 더함).
- 처리 단계(`status`): `received` → `extracted`(글 뽑음) → `indexed`(임베딩·벡터 저장) → `classified`(분류·요약). 실패는 `failed` + 까닭 글. 글 뽑기는 요청 안에서(대부분 수 초), **임베딩·분류는 뒤에서**(서버 안 작업 줄). 대화는 `extracted` 이면 바로 쓸 수 있다(그 사이 `files.read` 는 낱말 검색으로).
- 확장자별 처리:

| 종류 | 확장자 | 뽑는 것 |
|---|---|---|
| 그림 | png·jpg·jpeg·webp | 브라우저가 긴 변 1568px 로 줄인 사본(+원본 보관). 저장소 글 = 「그림 읽기」 모델이 쓴 설명(분류 단계에서) |
| 표 | csv·tsv | 행·열(표준 라이브러리), 앞 200행을 글로 |
| 엑셀 | xlsx | 시트별 표(openpyxl, 값만·수식 결과), 시트마다 앞 200행. xls 는 "xlsx 로 저장해 주세요" |
| PDF | pdf | 쪽별 글(pypdf), 앞 300쪽. 글이 거의 없으면 "스캔 문서라 글을 읽을 수 없습니다(OCR 미지원)" 표시, 파일은 보관 |
| 문서 | docx·hwpx | zip 안 XML 에서 글(표준 라이브러리) |
| 글 | txt·md | 그대로(UTF-8, 아니면 CP949 시도) |
| 안 받음 | hwp·dwg·mpp·zip·실행 파일 등 | 422 + "PDF 로 저장해 주세요" 같은 안내 |

- 임베딩 모델은 설정 상수 `CHRONOS_EMBED_MODEL`(기본 `openai/text-embedding-3-small`) **[내 판단]** — 바꾸면 차원이 바뀌어 다시 넣어야 하므로 화면 배정에 두지 않는다. **구현 첫 단계에 PM 이 직접 실측**(임베딩 1번, 키는 서브에이전트가 읽지 못함 — 27b·45 와 같은 방식). 임베딩이 실패한 파일은 `extracted` 로 두고 낱말 검색만 쓰며 칩에 「뜻 검색 준비 안 됨」, 다음 작업 때 다시 시도 **[내 판단]**.
- 조각: 약 800자 · 겹침 100자, 쪽·시트·행 위치를 달아 둔다(출처 표시용). 조각과 위치는 SQLite(FTS5 포함), 벡터는 Qdrant(payload: file_id·chunk_id·축 값).

### 5-2. 분류(축 고정 · 값 늘림) [PM]
- 축: **종류**(시방서·도면·공정표·계약·현장 사진·견적·회의록·법규·기타 … 늘어남) · **공종**(골조·전기·설비 …) · **현장**(일정 이름) · **시기**(자료가 다루는 달, 코드가 날짜 글에서 뽑거나 올린 달) · **출처**(대화 첨부·발주처·협력사 …).
- 에이전트(분류 단계, `light` 또는 「그림 읽기」)가 **지금 있는 값 목록을 받고** 축마다 값 하나 이상을 고른다. 맞는 것이 없을 때만 새 값을 만든다(strict JSON). 한 줄 요약도 함께. 새 값은 자료함에 「새」 표시.
- 바로 저장, 대화에 "자료함에 넣음: 시방서·골조·A현장 [고치기]" 한 줄 [PM]. 누구나 고칠 수 있다(지금 회사 전체 범위).
- 값이 한 축에 30개를 넘거나 비슷한 이름이 생기면 에이전트가 **합치기 제안** → 관리자가 승인(자료함 화면).

### 5-3. 세션 기억과 에이전트 도구
- 지우기 **[내 판단, 빌더 질문 6 — 내 규칙과 같은 방식]**: 올린 사람·관리자만. 실제로 지우지 않고 숨긴다(`files.deleted_at`) — 원본·조각·벡터는 남기되 검색·자료함 목록에서 뺀다. 이미 그 파일을 붙인 대화에서는 칩과 맥락 줄에 「(지워짐)」, `files.read` 는 "지워진 파일입니다". 관리자만 「완전히 지우기」(원본·조각·벡터 삭제).
- `chat_session_files`(대화 ↔ 파일). 대화 맥락에 매 턴 **「이 대화에 붙인 파일」** 줄: 파일마다 `id · 이름 · 종류 · 상태 · 한 줄 요약`(최대 20개, 넘으면 최근 것 + "외 n개").
- 도구:
  - `files.read {file_id, query?, page?}` — 붙인 파일에서 관련 조각(쪽·시트 위치 포함)을 돌려준다. 그림이면 설명 + (그림 읽기 모델 턴이면) 그림 자체.
  - `files.search {query, filters?: {축: [값]}, limit}` — 자료함 전체(지금은 회사 전체)에서 뜻 + 낱말 검색. 결과마다 파일 이름·위치·조각.
  - `files.classify` 는 두지 않는다(분류는 서버 단계가 한다). 사람 고침은 API.
- 답에 파일 내용을 쓸 때는 **출처(파일 이름·쪽)** 를 붙인다 — 지시문 조각 `guides/files.md`. 읽지 않은 내용은 말하지 않는다.

### 5-4. 공정표 파일 가져오기 [PM: 먼저 묻기]
- 공정표인지는 **에이전트가 판단**한다 [PM](파일을 읽은 뒤, 열 이름·내용을 보고). 공정표로 보면 대화에 **요약 카드**: 액티비티 수 · 찾은 열 · 빠진 것 · [일정 초안으로 가져오기]. 카드의 숫자(행 수 등)는 코드가 센다.
- 누르면: 에이전트가 열 대응을 정하고(strict JSON) 코드가 행을 액티비티로 바꾼다. **빈 칸(기간·선후·자원 등)은 에이전트가 판단해** 사람에게 물어야 하는 것은 기존 **질문지**로 묻고, 아니면 **추정**한다 [PM] — 지금 일정 생성(`agent/generation.py`)과 같은 길·같은 점검·고침 루프를 쓴다(에이전트는 기간·선후만, 날짜는 코드). 추정한 칸은 출처 「추정」으로 표시. 파일에 있던 값은 그대로 두고, 파일의 시작·끝 날짜는 에이전트가 판단해 제약(SNET 등)으로 둘지 정한다. 초안은 기존 첫 저장 길(승인함)로.
- 표가 공정표가 아니면 카드 없이 근거로만 쓴다.

### 5-5. 모델 고르기 · 그림 읽기
- 대화창 위 「모델 ▾」: 기본 = 설정의 대화 배정(`normal`). 고르면 **그 대화에만** 저장(`chat_sessions` 에 연결·모델·routing_strategy 칸). 목록은 설정의 모델 배정과 같은 모델 목록 + 가격 참고(Task 46).
- 적용 범위 **[내 판단]**: 에이전트 루프의 대화 호출만 바꾼다. 일정 생성·판단(`hard`)·분류(`light`) 같은 안쪽 작업은 설정 배정 그대로 — 까닭: 고른 모델이 strict JSON·도구를 못 하면 계산 길이 깨진다.
- 설정 「작업별 모델 배정」에 **「그림 읽기」(`vision`) 줄**을 더한다(기본 `liner-claude-router` balanced — 실측에서 그림 입력 토큰이 liner-mark 의 약 1/20).
- 그림이 붙은 턴은 **「그림 읽기」 모델로** 답한다 [PM]. 대화 모델을 따로 골랐어도 그 턴만 바뀌고 한 줄 안내: "그림이 있어 그림 읽기 모델(…)로 답합니다."
- 범위 **[내 판단, 빌더 질문 5]**: 「그림이 붙은 턴」 = 이번 메시지에 새 그림이 붙은 턴(그 턴의 모든 단계). 다음 턴부터는 그림의 **설명 글**만 맥락에 들어간다. 에이전트가 예전 그림을 다시 봐야 하면 `files.read {file_id, image: true}` 를 부르고, 루프가 그 그림을 `image_url` 메시지로 끼워 넣으며 그 단계부터 턴 끝까지 「그림 읽기」 모델로 바꾼다.

### 5-6. 정보 API 연결 · 날씨 도구 [PM]
- 표 `info_connections`(이름 · 종류 프리셋 · base_url · 키 암호문·끝 4자리 · 상태 · 확인 시각). 설정에 「정보 API 연결」 구역(관리자): 카드 · [연결 테스트] · 추가·삭제 — LLM 연결 화면과 같은 모양.
- PM 은 공공데이터포털 기상청 **ASOS 일자료·단기예보 키를 둘 다 가지고 있다** [PM]. 키는 PM 이 설정 화면에서 직접 넣는다. 실측은 PM 이 직접 돌린다(서비스마다 1번).
- 첫 프리셋 `kma_datagokr`(공공데이터포털 기상청): **ASOS 일자료**(과거, 지점 번호·기간)와 **단기예보**(3일, 격자 nx·ny). 키는 공공데이터포털 서비스키(인코딩 키) — 질의 `serviceKey` 로만 보내고 로그에 남기지 않는다.
- 위치: 내장 표(시·도와 주요 시 약 30곳 → ASOS 지점 번호·예보 격자). 에이전트는 표에 있는 이름만 고른다(없으면 가까운 곳을 묻는다).
- 도구 `info.weather {place, kind: "history"|"forecast", month?: 1..12, years?: 1..10, from?, to?}`:
  - history: 지난 n년(기본 10) 그 달 일자료 → **코드가** 평균기온·평균 최저·영하일수·강수일수(≥1mm)·최대 일강수 계산 → 근거로 저장(Task 27 근거 보관, 출처 "기상청 ASOS 일자료 · 공공데이터포털", 기준 기간).
  - forecast: 3일 예보의 하루별 최저·최고·강수확률.
  - 숫자는 **가정의 근거로만**, 날짜 계산에 넣지 않는다(지침에 명시). 실패면 Task 27 과 같은 안내 · 한도(요청당 3번).
- 연결 틀은 일반형(종류 프리셋으로 늘림) — 다른 정보 API 는 대회 뒤.
