# 연락처 프로그램과 문자·카카오톡·AI 전화 설계 (2026-11-23)

상태: PM 승인 대기 · 화면 시안 2차(메신저 꼴) https://claude.ai/artifact/Wn8a1mbMf3mPTzZ88dBgtQ (`docs/design/mockups/outreach-mockups.html`)

## 왜
지금은 현장 사람이 앱을 열어야만 요청을 본다. 협력사 담당자에게 문자·카카오톡·전화로 직접 닿게 하고, 주고받은 것을 일정과 함께 남긴다.

## PM 이 정한 것 (11-23)
- 시간보다 품질. 문자·카카오톡·전화 모두.
- 주소록은 협력사별이고 **프로젝트별로 격리**해 저장한다.
- 시연은 PM 본인 번호로만. 본선에 가면 다른 담당자 연락처를 넣는다.
- 새 프로그램 「연락처」를 만든다. 왼쪽은 주소록(이름·담당), 오른쪽은 대화창.
- 대화는 메신저처럼 말풍선. 보낸 사람 표기: 사람이 보내면 `[로그인한 이름 발신]`, 에이전트가 쓴 것은 `[에이전트 발신]`.
- 문자와 카카오톡은 한 대화에 섞여 보이고 입력창에서 고른다. 통화는 위 탭으로 바꾼다. 날짜가 바뀌면 줄을 긋는다.
- 연결 설정은 「LLM 연결」과 같은 꼴.

## 목표 / 하지 않는 것
- 목표: 프로젝트별 주소록, 한 사람과의 문자·카카오톡 대화와 통화 기록, 사람이 확인한 뒤에만 나가는 발송, 에이전트 초안, 결과(도착·실패·회신·통화 요약) 기록, 시험 모드.
- 하지 않는 것: 에이전트가 사람 확인 없이 보내기, 광고성 메시지(브랜드 메시지), MMS, 050 안심번호, 웹훅 수신(공개 주소가 없음 — 주기적 조회로 대신), 버튼 눌러 답하는 자동 안내 전화(VoiceML, 공개 주소 필요), 대량 캠페인.
- 실패로 보는 것: 허용하지 않은 번호로 실제 발송, 다른 프로젝트의 연락처가 보이거나 에이전트에게 읽힘, 키·전화번호가 모델·기록·로그에 그대로 남음, 같은 메시지 두 번 발송.

## 접근
- 화면 배치: 세 안(프로그램 하나 / 일정에서 보내기 / 둘 다)을 보였고 PM 이 메신저 꼴 프로그램을 골랐다. 일정·현장 화면에서 시작하는 길은 이 프로그램의 대화로 이어지게 덧붙인다.
- 결과 받기: 웹훅(공개 주소 필요) 대신 **주기적 조회**. 앱이 맥·테일넷 안에 있기 때문.
- 전화: 두 사람을 이어 주는 API 가 문서에 없다. **AI 음성 에이전트 통화**(통화마다 지시문·변수를 넘김)로 한다.

## 제공사 (한국AI통신, 문서 확인분)
- 인증: `Authorization: Bearer <API Key>`, 경로에 Account ID. `https://api.koreaaitel.com/v1/accounts/{accountId}/…`
- 문자·알림톡: `POST …/messages` (`To`, `From`, `Body` / `Kakao{ChannelId,TemplateId,Variables}` + `Fallback{Body}`, `IdempotencyKey`). 조회 `GET …/messages/{id}`, 목록 `GET …/messages?status=received&number=…`(회신 받기).
- 발신번호: 이 회사에서 개통한 070·대표번호만. 발급하면 바로 쓴다.
- 전화: `POST …/calls` (`To`, `From`, `AgentId`, `CallContext{Instruction,Variables}`, `Record`, `Timeout`). 조회 `GET …/calls/{id}`. 받아쓰기·요약·녹음 조회 API 가 있다(정확한 경로는 구현 때 문서로 확인).
- 알림톡: 카카오 채널 연결과 문안(템플릿) 검수 승인이 먼저다. 승인된 문안의 변수만 바꿀 수 있다.
- 한도: 문자 분당 120건.
- **구현 때 실제 계정으로 확인할 것**: 회신 목록 조회가 기대대로 되는지, 통화 받아쓰기·요약 경로와 걸리는 시간, `CallContext` 가 지시대로 말하는지, 상태 값의 실제 흐름.

## 자료 (모두 일정 = 프로젝트에 묶인다)
- `contact_companies`: 일정, 이름, 공종, 메모.
- `contacts`: 일정, 협력사, 이름, 담당(직책), 전화번호, 받을 수 있는 것(문자·카카오톡·전화), 메모, 숨김.
- `outreach_messages`: 일정, 연락처, 방향(보냄·받음), 채널(문자·카카오톡), 내용, 문안 id·변수, 시작한 쪽(사람·에이전트)과 이름, 보낸(승인한) 사람, 상태(초안·접수·도착·실패·시험 모드로 막힘·받음), 실패 까닭, 대신 보낸 문자 여부, 제공사 메시지 id, 중복 방지 키, 연결(작업·현장 항목·승인 건·대화), 묶음 id, 시각.
- `outreach_calls`: 일정, 연락처, 목적, 물어볼 것, 말하지 않을 것, 시작한 쪽·승인한 사람, 상태(초안·거는 중·통화됨·받지 않음·통화 중·실패·시험 모드로 막힘), 통화 시간, 요약, 받아쓰기, 결과(에이전트 제안 / 사람 확정), 제공사 통화 id, 연결, 시각.
- `notify_connections`: 이름, 공급자, 주소, 키(암호문·끝 4자리), Account ID, 발신번호, 카카오 채널 id, 문안 표(종류 → 문안 id·변수 이름), 음성 에이전트 id, 시험 모드(기본 켜짐), 허용 번호, 하루 상한(문자·전화), 상태, 확인 시각.

## 지켜야 할 규칙 (코드가 지킨다)
1. **보내기는 한 함수만 거친다.** 사람의 [보내기]·[전화 걸기] 요청에서만 불린다. 에이전트 도구에는 보내는 도구가 없다.
2. **시험 모드**가 켜져 있으면 허용 번호가 아닌 대상은 제공사를 부르지 않고 「시험 모드로 막힘」 기록만 남긴다. 서버에서 막는다(화면만이 아니라).
3. **프로젝트 격리**: 모든 조회·쓰기는 일정 id 로 거른다. 다른 일정의 연락처 id 를 넣으면 404.
4. **전화번호는 모델에게 주지 않는다.** 에이전트는 연락처 id·이름·담당·협력사·받을 수 있는 채널만 본다. 화면 목록은 가운데를 가리고 눌러서 본다. 기록·로그·trace 에는 가린 번호만.
5. **키**는 LLM 연결과 같이 암호화 저장·끝 4자리만 표시, 응답·오류·로그에서 지운다.
6. **중복 방지**: 메시지마다 고유 키를 제공사에 함께 보낸다. 같은 초안의 [보내기]를 두 번 눌러도 한 번만 나간다.
7. **하루 상한**을 넘으면 거절하고 까닭을 알린다. 받지 않은 전화는 자동으로 다시 걸지 않는다.
8. 제공사를 부르는 동안 DB 쓰기를 쥐지 않는다.

## 「연락처」 프로그램
- 왼쪽: 찾기 칸, 협력사별 묶음, 사람 줄(이름·담당·새 회신 수·번호 없음 표시). 아래에 사람 추가·협력사 추가·CSV 가져오기.
- 오른쪽 머리: 이름·담당·협력사, 가린 번호, 받을 수 있는 채널, 탭 `문자 · 카카오톡` | `통화 n`.
- 문자·카카오톡 탭: 날짜 줄, 말풍선(보낸 것 오른쪽·받은 것 왼쪽). 말풍선 위에 `[이름 발신]` 또는 `[에이전트 발신] · 승인한 사람`, 채널 표시, 시각. 아래에 상태(도착·실패 → 문자로 대신 보냄·시험 모드로 보내지 않음)와 연결된 작업.
- 에이전트 초안: 점선 말풍선 + [버리기][고치기][보내기]. 보내기 전에는 나가지 않는다.
- 입력창: `문자 | 카카오톡` 고르기, 연결할 작업, 글자 수·건수, [에이전트에게 초안 맡기기], [보내기]. 카카오톡을 고르면 승인된 문안 고르기 + 변수 채우기로 바뀐다(승인된 문안이 없으면 고를 수 없고 까닭을 보인다).
- 통화 탭: 날짜 줄, 통화 카드(상태·시간·요약·결과·[받아쓰기][녹음][결과 확정]·받지 않으면 [다시 걸기]). 아래 [전화 걸기] → 목적·물어볼 것·말하지 않을 것·연결을 확인하는 창.
- 시험 모드면 창 머리에 「시험 모드 · 허용 번호 n개」가 늘 보인다.
- 권한: 관리자·사용자가 쓴다. 현장 관리자는 열 수 없다.

## 다른 화면에서 시작하기
- 스케줄·간트의 작업 행 [연락] → 그 작업 공종의 협력사 사람을 고른 채 「연락처」가 열린다.
- 현장 허브의 체크인 일괄 발송·의견 조회·핸드오프 → 받는 사람·내용 확인 창 → 보낸 것은 각 사람의 대화에 들어가고 묶음 표시가 붙는다.
- 승인함의 대기 건 → 승인권자에게 알리기.
- 대화에서 에이전트에게 요청 → 초안 카드 + 「연락처」의 점선 말풍선.

## 에이전트 도구
- `contacts.list` — 이 일정의 협력사·사람(번호 없음).
- `notify.draft_message` — 받는 사람·채널·내용·연결을 넣어 초안을 만든다(보내지 않음).
- `notify.draft_call` — 받는 사람·목적·물어볼 것·말하지 않을 것으로 통화 초안을 만든다(걸지 않음).
- `notify.status` — 보낸 것·통화의 결과와 회신을 읽는다(답의 근거).

## 설정 「알림 연결」 (LLM 연결과 같은 꼴)
- 카드: 이름·공급자·상태·주소·키 끝 4자리·확인 시각, [연결 테스트][주소 수정][키 교체][삭제].
- 추가로: Account ID, 발신번호, 카카오 채널·문안 표, 음성 에이전트 id, 시험 모드·허용 번호, 하루 상한.
- [연결 테스트]: 돈이 들지 않는 조회(발신번호 목록)로 키·Account ID·발신번호 승인 여부를 본다. [시험 문자]·[시험 전화]는 허용 번호 첫 번째로 한 건 보낸다.

## 만드는 차례
1. 서버 뼈대: 표, 알림 연결, 제공사 호출, 보내기 함수(시험 모드·상한·중복 방지), 상태·회신 조회 일꾼.
2. 「연락처」 프로그램: 주소록, 문자 대화, 입력창.
3. 에이전트 도구와 초안, 대화 카드.
4. 통화: 걸기 창, 통화 탭, 요약·받아쓰기.
5. 카카오톡: 문안 표, 고르기, 대신 보내기 표시.
6. 다른 화면에서 시작하기(스케줄·현장 허브·승인함).
단계마다 검토하고, 실제 발송 확인은 PM 번호로만 한다.

## PM 이 준비할 것
가입·070 번호 발급, API Key·Account ID, 카카오톡 채널 연결과 문안 검수 신청(문안 초안은 따로 드림), 음성 에이전트 만들기(지시문 초안은 따로 드림).

## 만드는 사람에게 남기는 것
표·칸의 정확한 이름, 조회 간격, 프로그램 색·아이콘, CSV 열 이름, 말풍선 세부 모양.
