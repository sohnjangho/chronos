# 검색 근거 다시 쓰기 설계 (2026-11-23)

상태: PM 승인(11-23) — 제안대로, 유효 기간 30일, 시나리오 재검증 전에 만든다.

## 왜
Liner 검색으로 찾은 근거(기준·법규·사례)를 다른 대화에서 같은 주제를 물을 때 다시 검색하지 않고 꺼내 쓴다. Liner 호출과 대기가 줄고, 같은 질문에 같은 근거가 나온다. "학습"은 모델 훈련이 아니라 저장해 두고 먼저 찾아보는 것이다.

## 목표 / 하지 않는 것
- 목표: 근거 검색(`evidence.search`)이 저장된 근거를 먼저 찾고, 맞는 것이 있으면 Liner 를 부르지 않는다. 언제 찾은 근거인지 보인다. 30일이 지난 근거는 다시 쓰지 않고 새로 찾는다. 사용자가 "다시 찾아 줘"라고 하면 새로 찾는다.
- 하지 않는 것: 공공데이터 API 결과(날씨 `weather`·범용 `info`) 다시 쓰기 — 실시간 값이라 틀린 답이 된다. 자료함 화면에 근거를 파일처럼 보이기. 근거 내용 고치기.
- 실패로 보는 것: 관계없는 저장 근거를 맞는 근거처럼 내놓는 것, 낡은 근거를 새것처럼 보이는 것.

## 접근
- A. 검색된 결과를 모두 저장해 다시 쓴다 — 관계없는 결과까지 쌓인다.
- **B. 실제로 쓰인 근거만 다시 쓴다(PM 선택).** 가정·조건·일정에 붙은 근거(`evidence_links` 가 있는 것)만 다시 쓸 대상이다.
- 맞는지의 판단은 에이전트가 한다(PM 원칙: 판단은 에이전트, 계산은 코드). 코드는 후보를 찾아 주고 날짜·기간을 계산한다.

## 동작
1. `evidence.search {query, mode, fresh?}` 를 부르면 코드가 먼저 저장된 근거에서 찾는다.
   - 대상: mode 가 web·scholar·legal·business 이고, 붙은 곳이 하나 이상 있고, 찾은 지 30일 안이고, 「다시 쓰지 않기」가 아닌 근거. 회사 전체가 함께 쓴다(대화·일정을 가리지 않음).
   - 찾는 법: 낱말 검색(제목·요약·그때의 검색어) + 뜻 검색(Qdrant 가 켜져 있을 때). 뜻 검색이 꺼져 있으면 낱말만.
   - 코드가 정한 최소 관련도 아래는 버린다. 남은 것이 있으면 상위 5개까지 돌려주고 Liner 는 부르지 않는다.
2. 돌려주는 결과에 `reused: true` 와 근거마다 `searched_at`(찾은 날)·`age_days` 를 넣는다. 안내 한 줄: 「저장된 근거입니다. 질문에 맞지 않으면 fresh 를 true 로 다시 부르세요.」 다시 쓴 호출은 한 요청 3번 한도에 세지 않는다(Liner 를 안 불렀으므로). 그래도 같은 요청에서 다시 쓰기는 5번까지.
3. 후보가 없거나 `fresh: true` 면 지금처럼 Liner 를 부르고 결과를 저장한다(한도에 센다).
4. 다시 쓴 근거의 `evidence_id` 는 원래 것 그대로다 — 가정에 그대로 붙인다.
5. 30일이 지난 근거는 다시 쓰기 대상에서 빠진다. 지우지는 않는다(이미 붙은 일정의 근거 기록은 그대로).

## 화면
- 근거 카드: 다시 쓴 결과는 머리에 「저장된 근거 · 11-20 검색」 표시. 줄마다 [다시 쓰지 않기](누르면 그 근거는 앞으로 다시 쓰지 않는다 — 되돌리기 가능).
- 다른 화면은 바꾸지 않는다.

## 에이전트 지침
- 기준·법규·사례 같은 글 근거는 `evidence.search`(Liner). 일정 날짜를 움직이는 값·실시간 상태(날씨 통계·예보·공휴일·특보)는 정보 API(`info.weather`·`info.call`)를 먼저 쓴다.
- `reused` 결과가 질문에 맞으면 그대로 쓰고, 맞지 않거나 사용자가 다시 찾아 달라고 하면 `fresh: true`.

## 만드는 사람에게 남기는 것
색인 방식(FTS5 표·Qdrant 컬렉션 이름), 최소 관련도 값, API 경로 이름, 카드 세부 배치.
