## 1. 문제 정의 (30%) — 「밤새 고친 공정표, 아침이면 또 바뀐다」

### 1-1. 누가, 언제, 얼마나 불편한가
건설·플랜트·생산 현장의 스케줄은 **하루에도 수십 번 바뀝니다.** 비가 오고, 자재가 늦고, 장비가 겹치고, 발주처가 마일스톤을 당깁니다.

| 역할 | 현장에서 매일 하는 일 | 겪는 병목 |
|---|---|---|
| **공정 담당** | 주간 진도 갱신, 지연 시 만회 계획 작성 | 수십 가지 조건을 밤새 손으로 맞췄더니 다음 날 또 변경 |
| **PM** | 지연 원인 파악, 발주처 보고, 변경 승인 | 공종별 시방서·근거 취합과 영향 검토에 반나절 이상 소요 |
| **현장소장** | 3주 룩어헤드 확인, 자재·장비 투입, 현장 보고 | 사무실 공정표와 현장 사진·지연 상황이 따로 돎 |

| 반복되는 현장 업무 | 기존 소요 시간 | 병목 원인 |
|---|---|---|
| 진도 5% 지연 시 만회 계획 수립 | 반나절 ~ 밤샘 | 수십 가지 제약·크리티컬 패스 수작업 재계산 |
| 발주처 요구로 마일스톤·조건 변경 | 하루 | 자원 겹침·선후행 연쇄 영향 즉시 확인 불가 |
| 공종별 전문가(골조·전기·설비) 검토·협의 | 매주 수 시간~며칠 | 문서·도면이 흩어져 있고 변경 근거 추적이 어려움 |
| 협력사 엑셀 공정표 취합·검토 | 건당 2~3시간 | 양식 제각각, 빈 칸 확인, 수기 입력 |

### 1-2. 왜 기존 도구도, 일반 AI도 못 푸는가
| 구분 | 기존 방식 | ChronOS |
|---|---|---|
| **전문 공정 도구 (P6 등)** | 비싸고 배우기 어려움, 현장 문서·AI와 단절 | 대화 한 줄 + 동적 질문지로 시작, OS 창에서 즉시 조작 |
| **엑셀 공정표** | CPM·자원 맞춤 계산이 없어 사람이 밤새 손으로 계산 | 결정론적 코드 엔진(`app/core`)이 1초 만에 재계산 |
| **범용 AI 챗봇** | 공정표를 넣으면 날짜·크리티컬 패스가 깨지고 검증 불가 | **계산은 코드 · 판단은 Liner · 결정은 사람(승인함)** |

## 2. 솔루션 & 완성도 (30%) — ChronOS

### 2-1. AI · 코드 엔진 · 사람 역할 분담
ChronOS는 AI가 만능인 것처럼 쓰지 않습니다. 각자 가장 잘하는 영역을 엄격히 나눕니다.

| 단계 | Liner AI | 코드 엔진 · 하네스 | 사람 (PM · 공종) |
|---|---|---|---|
| 요청 해석 · 조건 추출 · 질문지 생성 | ✅ | — | 답하거나 가정 확인 |
| 날짜 · 여유(Float) · CPM · 자원 맞춤 계산 | — | ✅ (환각 0%) | — |
| 4겹 하네스 조건 점검 (기본·분야·내 규칙·입력) | — | ✅ | 조건 수정·규칙 추가 |
| 위반 시 초안 고침 · 만회안 설명 및 추천 | ✅ | ✅ (후보 탐색) | 비교판에서 선택 |
| 시방서·사진 5축 분류 · 법규/날씨 근거 조사 | ✅ | ✅ (Qdrant·기상청) | 축 수정·출처 확인 |
| 준공·마일스톤·크리티컬·조건 변경 최종 확정 | — | — | ✅ 승인함 승인/거부 |

### 2-2. 하지 않는 것 (신뢰를 만드는 경계)
| 하지 않음 | 이유 |
|---|---|
| **LLM이 날짜·여유·자원 겹침을 계산하지 않음** | LLM 날짜 계산은 틀린다. LLM이 보낸 날짜는 코드가 버린다 |
| **자동 점검 안 되는 조건을 통과로 보이지 않음** | 코드로 잴 수 없는 조건은 「자동 점검 안 됨」으로만 표시한다 |
| **중요 변경을 사람 승인 없이 반영하지 않음** | 일정 변경은 책임이 큰 결정. 승인함에서 거부하면 사유를 반영해 다시 짠다 |
| **근거 없는 법규·기상 수치를 지어내지 않음** | Liner Search/MCP·기상청 API 출처가 없으면 기본값/미확인으로 밝힌다 |

## 3. Liner API 활용 (20%) — 5종 API 전수 연결·검증

| Liner API | 핵심 활용 역할 | 실측 검증 |
|---|---|---|
| **Model & Router API** | 작업 난이도별 배정: `light(cost)` 조건 추출·분류 / `normal(balanced)` 대화·ReAct / `hard(quality)` 생성·고침·만회안 추천 / `longdoc` `liner-mark`(1M 토큰) / `vision` 사진 읽기. 대화별 `모델 ▾` 교체 | 22/22회 200 OK (도구 호출·JSON 스키마·전략별 라우팅) |
| **Search API** (`web`·`scholar`) | 시공 기준·공정 가정 근거 검색(`evidence.search`), 결과 보관 및 조건 출처 링크 연결 | 200 OK · 출처 URL 보관 |
| **MCP** (`search_legal`·`search_business`) | 건설 법규·인허가 기간·공급업체 납기 조회(출처 인용 필수) | 5/5회 200 OK (Streamable HTTP) |
| **Visualization API** | 공정률·지연·비교 보고서용 차트 HTML 생성 + **코드가 그림 속 숫자를 표와 전수 대조**(불일치 시 자체 차트 폴백) | 2/2회 200 OK (표 값 15/15 일치) |
| **Embeddings API** (`3-small`) | 5축 자료함 Qdrant 벡터 뜻 검색 + 모델 변경 시 무중단 백그라운드 재색인 | 1536차원 · 1.1초 · $0.02/1M 토큰 |

## 4. 확장성과 임팩트 (20%)

### 4-1. 정량적 시간 절감 (공정 담당 1인 기준 주당 6~8시간 절감)
| 반복 업무 | 기존 | ChronOS 적용 후 |
|---|---|---|
| 지연 만회 계획 수립 | 반나절 ~ 밤샘 | 대화 한 줄 → 만회안 탐색(1초대) + 비교판 즉시 비교 (**30분 이내 결정**) |
| 조건·자원 시뮬레이션 | 수작업 재작성 (수 시간) | 값 변경 즉시 간트 점선 미리 보기 (**1초 미만**) |
| 회의록·시방서·근거 반영 | 매주 2시간+ | 5축 자료함 뜻+낱말 검색 + 법규·날씨 출처 자동 첨부 (**20분 이내**) |
| 협력사 공정표 취합 | 건당 2~3시간 | 엑셀/CSV 첨부 → 자동 감지 → 빈 칸 질문지/추정 (**20분 이내**) |

### 4-2. 산업 · 직무 · 디바이스 확장
- **타 산업 (이미 실증 + 전 산업 동적 합성)**: **건설(5층 사무동 신축, 59개 액티비티)**과 **생산(가상 부품 공장 브래킷 BR-200, 30개 액티비티·설비 자원별 간트)** 2종의 전문 분야 팩을 구현 완료했고, **`domain_synth.py` 범용 도메인 동적 합성**으로 R&D·조달·소프트웨어 등 어떤 산업의 첫 질문이 들어와도 용어·WBS 계층·위험 규칙을 즉석에서 생성해 동일 엔진으로 처리합니다.
- **타 직무 · 조직**: 같은 OS 엔진 위에 원가·품질·안전 도구를 추가할 수 있으며, 중소 기업도 고가의 P6 없이 CPM·자원 맞춤·승인 관리를 쓸 수 있습니다.
- **본사 PC + 현장 태블릿·스마트폰**: PC OS 멀티태스킹(`Desktop`) + iPadOS형 좌우 분할 **`TabletShell`** + 390px **`MobileShell`** 3-디바이스 자동 감지·수동 전환과 **`FieldHub` 4종 협업**(일일 체크인·사진 AI 판독·만회안 의견·D-3 핸드오프)으로 본사와 현장이 실시간으로 연결됩니다.
