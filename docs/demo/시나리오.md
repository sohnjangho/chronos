# 데모 영상 시나리오 — 초안 (묶음 1 + 묶음 2)

> 5분 이내 · FHD 1920×1080 · 밝은 테마 · 화면 녹화 + 말(자막 겸용).
> 범위: 묶음 1(대화로 만들기 · 질문지 · 생성 회차 · 승인 · 간트·CPM · 조건 미리 보기 · 버전 되돌리기) +
> 묶음 2(지연 → 영향 → 만회안 → 비교판 → 승인 · CPM 요약·공정률 · 개발 콘솔 · 두 번째 분야). 두 묶음을 한 영상 5분에 넣는 자르기는 아래 「정할 것」.
> 예시 자료는 전부 가상이다(「5층 사무동 신축」, 계정 demo-admin).

## 촬영 전 준비

| 할 일 | 방법 |
|---|---|
| 깨끗한 자료 폴더 | 시연 전용 `CHRONOS_DATA_DIR`(PM 앱의 `data/` 와 따로) |
| 예시 일정 | `python -m app.seed demo` — 시연 일정 둘: 「5층 사무동 신축」(건설·L3, 액티비티 59개·조건 14개·주요 자원 3개, 실적 일부·Data Date 2027-04-17) · 「가상 부품 공장 — 브래킷 BR-200 2만 개」(생산·L3, 액티비티 30개·주요 자원 6개, 납기 2027-09-10, 실적 없음 — 간트는 자원별로 묶이고 「프레스 작업 금지」 띠·「납기 09.10」 선이 보인다) |
| 스케줄 칸 | 스케줄표의 열 고르기는 사람마다 저장된다. 한 번이라도 열을 고른 사람은 생산 일정에서도 「주요 자원」 칸이 저절로 켜지지 않으니 [열]에서 직접 켠다 |
| Liner 연결 | 설정 > LLM 연결에 키, 작업별 배정은 기본값(light=cost · normal=balanced · hard=quality) |
| 승인 수준 | 「중요한 것만」(기본값) — 첫 저장·조건 바꿈이 승인함으로 간다 |
| 리허설 | `bash scripts/e2e-local.sh` 로 화면 흐름 확인(가짜 LLM). 실제 촬영은 Liner 로 |
| 예비 | 생성이 느리거나 실패하면 장면 3을 씨앗 일정으로 바로 넘어간다(말은 그대로) |

## 묶음 2 장면 (지연 → 영향 → 만회안 → 승인, 두 번째 분야)

씨앗을 다시 넣고(`python -m app.seed demo`) 찍는다 — 아래 버전 번호(승인 뒤 버전 3)와 숫자는 씨앗 그대로일 때 값이다. 묶음 1 장면 7(버전 2로 되돌리기 → 버전 4) 뒤에 이어 찍으면 일정 내용은 같고 승인 뒤 버전만 5 가 된다. 시간은 묶음 2 만 따로 잰 초안이다.

합계 3:10(묶음 2 만). 숫자는 씨앗 일정을 코드가 계산한 값이다(`backend/tests/e2e/test_bundle2_flow.py` 와 화면 시험이 확인). 실제 촬영에서는 Liner 가 추천·설명을 쓰므로 추천 안과 설명 글이 화면 시험(가짜 LLM — 설명은 「시연용 가짜 LLM 설명」, 추천은 코드 추천)과 다를 수 있다.

공정률은 **승인 전(B3)** 에 보인다. 승인 뒤(B7)는 CPM 의 「만회 계획 달성률」과 완료 예정 날짜만 말한다. 만회안 승인은 계획 변경이라 Plan 이 그 승인 때의 예측(10.01)으로 고정된다(PM 규칙 — Task 16e) → **승인 직후 계획대로(편차 0)**, 이후 실적이 늦으면 늦음 +n 으로 보인다. 말할 때 주의: 승인 직후 0 인 것은 **준공(프로젝트 완료) 편차뿐**이다 — 공정률의 계획·실적 차이와 일정 수행 지수(SPI)는 Plan 곡선이 기간 비례로 펴져 있어 승인 직후에도 꼭 0·1.00 이 되지 않는다. 「공정률이 계획과 같아졌다」고 말하지 않는다.
