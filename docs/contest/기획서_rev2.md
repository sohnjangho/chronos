## 0. 핵심 요약 (Executive Summary)

현장의 일정은 매일 바뀝니다. ChronOS는 바뀐 현장을 **10분 안에 다시 계산**하고, 법규·시방서·기상청 근거를 붙여, **사람이 바로 결정**하게 만드는 일정 관리 OS입니다.

### 0-1. 현장의 3대 병목과 ChronOS 도입 후 변화
| 구분 | 기존 현장 (Before) | ChronOS 도입 후 (After) |
|---|---|---|
| **공정 지연 · 만회 계획** | 비·자재 지연 시 선후행·장비 겹침을 엑셀로 밤새 수작업 재계산 (반나절~밤샘) | 대화 한 줄·현장 사진으로 1초 영향 계산 & 만회안 A/B 같은 차트 비교 (**10분 이내 결정**) |
| **근거 확인 · 현장 협의** | 시방서·법규·날씨 따로 찾고 사무실-현장 전화·회의 반복 (수 시간~며칠) | 5축 자료함·법규(MCP)·기상청 근거 자동 첨부 & 현장 모바일 1분 체크인·의견 취합 (**20분 이내**) |
| **신규 일정 · 협력사 취합** | 고가 SW(P6) 없인 수작업 작성, 제각각인 협력사 엑셀 취합 (건당 2~3시간) | 2단계 맞춤 질문지로 전 산업 일정 즉석 생성 & 협력사 엑셀 빈칸 자동 보완 (**20분 이내**) |

### 0-2. 코드 · Liner AI · 사람의 3단 분업
1. **코드 계산 엔진 (`날짜 오차 0%`)**: AI는 날짜 덧셈을 하지 않습니다. 근무 달력·공휴일·장비 용량·선후행 관계를 전용 코드 엔진이 1초 만에 계산하고 4겹·8종 안전장치(하네스)로 규칙 위반을 차단합니다.
2. **Liner 5종 AI (`판단·근거·차트`)**: 난이도별 모델 분배(`Router`), 사내 시방서 기억(`Embeddings`), 공법·법규·납기 조사(`Search`·`MCP`), 보고 차트 생성(`Visualization`·표 숫자 전수 대조)까지 5종 API가 한 흐름으로 작동합니다.
3. **15개 앱 OS & 사람 승인 (`현장 연결`)**: 단일 챗봇이 아니라 간트차트·비교판·승인함 등 15개 앱이 PC·태블릿·스마트폰에서 실시간 연동되고 AI가 필요한 창을 자동 전환하며, 중요 변경은 사람이 승인함에서 최종 확정합니다.

## 1. 문제 정의 (30%) — 「밤새 고친 공정표, 아침이면 또 바뀐다」

### 1-1. 누가, 언제, 얼마나 불편한가
건설·플랜트·생산 현장의 스케줄은 **하루에도 수십 번 바뀝니다.** 비가 오고, 자재가 늦고, 장비가 겹치고, 발주처가 준공 목표일(마일스톤)을 당깁니다.

> **쉬운 용어 안내 (비전공자 기준)**  
> - **크리티컬 패스(Critical Path)**: 이 작업이 하루 늦어지면 전체 준공일도 하루 늦어지는 가장 중요한 작업 연결선  
> - **여유(Float)**: 전체 준공일을 밀지 않고 작업을 뒤로 늦출 수 있는 허용 일수  
> - **3주 룩어헤드(Lookahead)**: 앞으로 3주 안에 착수할 작업에 자재·장비·선행 작업 빠진 것이 없는지 미리 점검하는 표

| 역할 | 현장에서 매일 하는 일 | 겪는 병목 |
|---|---|---|
| **공정 담당** | 주간 진도 갱신, 지연 시 만회 계획 작성 | 수십 가지 조건을 밤새 손으로 맞췄더니 다음 날 또 변경 |
| **PM (총괄 책임자)** | 지연 원인 파악, 발주처 보고, 변경 승인 | 공종별 시방서·근거 취합과 영향 검토에 반나절 이상 소요 |
| **현장소장** | 3주 룩어헤드 확인, 자재·장비 투입, 현장 보고 | 사무실 공정표와 현장 사진·지연 상황이 따로 돎 |

| 반복되는 현장 업무 | 기존 소요 시간 | 병목 원인 |
|---|---|---|
| 진도 5% 지연 시 만회 계획 수립 | 반나절 ~ 밤샘 | 수십 가지 제약·크리티컬 패스 수작업 재계산 |
| 발주처 요구로 마일스톤·조건 변경 | 하루 이상 | 자원 겹침·선후행 연쇄 영향 즉시 확인 불가 |
| 공종별 전문가(골조·전기·설비) 검토·협의 | 매주 수 시간~며칠 | 문서·도면이 흩어져 있고 변경 근거 추적이 어려움 |
| 협력사 엑셀 공정표 취합·검토 | 건당 2~3시간 | 양식 제각각, 빈 칸 확인, 수기 입력 |

### 1-2. 왜 기존 도구도, 일반 AI도 못 푸는가
| 구분 | 기존 방식 | ChronOS |
|---|---|---|
| **전문 공정 도구 (Primavera P6 등)** | 비싸고 배우기 어려움, 현장 문서·AI와 단절 | 대화 한 줄 + 맞춤 질문지로 시작, 15개 OS 창에서 즉시 조작 |
| **엑셀 공정표** | CPM(최단 준공·여유 계산)·자원 맞춤 계산이 없어 밤새 손으로 계산 | 결정론적 코드 엔진(`backend/app/core`)이 1초 만에 재계산 |
| **범용 AI 챗봇** | 공정표를 넣으면 날짜·여유(Float)가 깨지고 검증·승인 절차 없음 | **계산은 코드 · 판단은 Liner · 결정은 사람(승인함)** |

### 2-4. 개발자 관점 핵심 아키텍처 & 알고리즘 (`backend/app` · `frontend/src/os`)
- **결정론적 스케줄링 코어 (`backend/app/core/`)**
  - `calendar.py` (`WorkCalendar`, `_Workdays`): `[lo, hi)` 구간 근무일 서수 배열을 `@lru_cache`로 캐싱하고 `bisect_left`/`bisect_right` 이분 탐색(`O(log N)`)으로 대체공휴일 및 해를 넘기는 금지 기간(`BlockedPeriod`)을 반영해 날짜 연산을 9배 고속화했습니다.
  - `cpm.py` (`compute`, `_topological_order`): Kahn 위상 정렬(heapq)로 선후행 순환(`ScheduleError("cycle")`)을 탐지하고 `FS/SS/FF/SF`+`Lag`, `SNET/FNLT`, `Data Date` 기준 전진·후진 패스로 `ES/EF/LS/LF`와 `TF/FF`를 계산합니다.
  - `resources.py` (`level`, `_order`, `_slot`): `(ES, TF, id)` 최소 힙 우선순위로 일일 `capacity` 초과를 회피하는 가능 시작 슬롯을 탐색(`pinned_start`)하고 후행 작업으로 전파합니다.
  - `shorten.py` (`shorten`, `_grow`, `_Search`): 병행(`parallel`)·압축(`compress`)·자원 추가(`add_resource`) 후보 수마다 `level(s, compute(s))`를 다시 계산해 이동하는 크리티컬 패스를 추적하며 묶음 A·B·C를 생성합니다.
- **4겹 하네스 & 격리 차단 시험 (`backend/app/harness/`, `programs/devconsole/`)**
  - `assemble.py` (`assemble`, `_contest`): `BASE_RULES`(4순위) < 분야 규칙 `domain`(3순위) < 내 규칙 `mine`(2순위) < 입력 조건 `inputs`(1순위) 우선순위로 경합·`overridden_by`를 판정하며, `checks.py` (`check`)는 `text_only`/`duration_per_unit`를 `uncheckable`로 분리합니다.
  - `devconsole/catalog.py`: 임시 DB 트랜잭션 격리·롤백 기반으로 하네스 8종(`H-CPM-01`~`H-IN-01`) 위반 차단 응답 JSON을 버튼 하나로 즉석 검증합니다.
- **에이전트 루프 · 동적 컨텍스트 · 정밀 수리 (`backend/app/agent/`, `store/skills.py`)**
  - `loop.py`: `MAX_STEPS=12`(`store/settings.py` 설정 연동 시 `4~24`)턴 ReAct 루프, 도구 실행 전 커밋 및 실패 시 DB 롤백, `enable_self_reflection` 활성 시 `{error, reflection}` 진단 JSON 주입 및 `self_corrected` 텔레메트리 기록.
  - `context.py`: `build_context`가 `select_guides`(요청·화면 맞춤 지침 선택), `compact_older_note`(최근 대화 외 요청 압축 요약), `date_helper`(연도 자동 보정), `match_skill`(`score >= 2` 트리거 매칭 시 `skill_prompt_block` 주입)을 조립합니다.
  - `generation.py` & `domain_synth.py`: 2단계 인터뷰(`make_questionnaire.py`, `CARD_LIMIT=2`) → 비정형 산업 `DomainPack` 동적 합성 → Strict JSON(`WBS_SCHEMA`, `SCHEDULE_SCHEMA`, `REPAIR_SCHEMA`) → `DraftProblem` 시 깨진 액티비티/고리 ID(`cycle_ids`) 지목 + 기존 `self.draft` AST 보존 정밀 수리(최대 5회).

## 3. Liner API 활용 (20%) — 5종 API 전수 연결·검증

| Liner API | 핵심 활용 역할 | 실측 검증 |
|---|---|---|
| **Model & Router API** | 작업 난이도별 배정: `light(cost)` 조건 추출·도메인 합성·분류 / `normal(balanced)` 대화·ReAct / `hard(quality)` 생성·고침·만회안 추천 / `longdoc` `liner-mark`(1M 토큰) / `vision` 사진 읽기. 대화별 `모델 ▾` 교체 | 22/22회 200 OK (도구 호출·strict JSON·전략별 라우팅) |
| **Search API** (`web`·`scholar`) | 시공 기준·공정 가정 근거 검색(`evidence.search`), 결과 보관 및 조건 출처 링크 연결 | 200 OK · 출처 URL 보관 |
